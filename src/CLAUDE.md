## Live values & connection state

⚠️ **Live values are streamed BY SUBSCRIPTION, never wholesale.** The editor declares what it is looking at — open POU tabs + watch table + globals + HMI bindings — as key PREFIXES (`prog_<Name>_`; `prog__` covers every global AND `prog____exec_us_*`) plus a few explicit names, so it stays a few hundred bytes instead of thousands of keys: `App.jsx liveSubSig` → `host.liveSubscribe` (local sim — `host-agent/livefilter.go`; both pollers rebuild their plan when its generation moves) and `/stream/vars?p=&v=` (remote — `streamVarMatcher` + `ReadVariablesFiltered`, matched per tick against the CURRENT table since a redeploy replaces it under a live stream). ⚠️ **An EMPTY subscription means EVERYTHING** — the state at sim start and what an older editor or KronServer leaves, so narrowing is always explicit and back-compat is free. ⚠️ The signature is keyed off a JSON **string**, not the objects it is built from (`projectStructure` changes on every keystroke and a remote change costs an SSE reconnect — a connection's filter is fixed for its life), and keys leaving the subscription are **dropped from `liveVariables`**, else they freeze at their last value and read as live. HMI bindings are in the set because the local sim feeds the HMI server from `liveVariables`.

⚠️ **Forced variables are shown CODESYS-style** (red-framed "F" via `ForcedMarker`/`ForcedContext`, Force list tab in OutputPanel with Unforce / Unforce All, orange "FORCED (n)" toolbar button; ForceWriteModal has Release = `unforce`). The set arrives as the reserved `__forced` key (KronServer: inside `/stream/vars` events; local sim: BESIDE `vars` in `simulation-output`) — ⚠️ split it off (`splitForcedPayload`), never merge it into `liveVariables`; a missing key means unchanged. RungContainer reads it through the context, never node data (keeps `mapBlocksToNodes` deps clean). Writes are serialised PER KEY (`forceChainsRef`) so a release can't overtake its press.
⚠️ **Switching project DETACHES from what runs** (`detachRuntimeForProjectSwitch` in close/open/new/pull): the local sim is stopped (confirm first), refs + `liveVariables` + forced set cleared; a remote PLC keeps running. Close used to orphan the privileged loader-host while the new project showed the old program's live values.
⚠️ **Remote force-write keys** = Build & Send's `remoteVarKeysRef` ∪ every key the target has STREAMED (`remoteStreamedKeysRef`) — after a browser reload the first is empty and writes were silently dropped; an unknown key now logs a warning.

**Re-attach after a browser reload:** `GET /api/host/sim-status` → `{running, pid, mode}`; an effect guarded by `simReattachedRef` restores the flags plus `hotSwapActiveRef`/`taskSigRef`. ⚠️ For a **remote** PLC the 3 s `checkStatus` poll starts the SSE **unconditionally** — `remoteVarKeysRef` is set only by Build & Send in the same session.
⚠️ **Liveness is `PLCClient.isStreamHealthy` (last event < 5 s), NEVER `isStreaming`** — EventSource retries a dead host forever with readyState stuck at CONNECTING, so a powered-off target stayed **Connected/Running** with frozen values; 2 failed polls now drop the stream+client and clear `isRunning`.

## Frontend architecture
⚠️ **Unified rung-based POU model.** Every program/FB/function is a **list of rungs**, each authored in LD or ST; `SCL` IS this model and is the **only** type the UI creates (`content:{rungs, variables}`), with `normalizePouToRungs` folding legacy `ST`/`LD` POUs on load. The transpiler dispatches on `pou.type` and handles `SCL` per rung, so an all-LD unified POU produces identical codegen to a legacy `LD` POU. **Do not reintroduce a create-time language picker** — language is per rung.

**Rung UX (`RungEditorNew.jsx`):** the rung header's language pill is a `convertRungLang` button. ⚠️ **Inline declaration (LD):** committing a block whose name isn't declared auto-creates it (contacts/coils → BOOL, FB → an instance of that type) as `class:'Local'` in the same history step.
- ⚠️ **Pin datalists for the families** (`ANY_NUM/ANY_INT/…`) are **always rendered even when empty** — a missing datalist id silently kills autocomplete. `POLY_NUM_BLOCKS` narrows pin `type` for display but sets **`suggestType:'ANY_NUM'`**, which `getPinSuggestionList` prefers, so a literal in IN1 doesn't collapse the other pins.

**Read-only mode (`isRunning`)** disables `VariableManager`, sidebar edits and `ResourceEditor`, but **logic editors are additionally gated by `allowLiveEdit`** (= `(isRunning && isHotSwap) || fieldHotSwap`), so a live hot-swap allows online ST/ladder editing while layout-owning editors stay locked. Editing while running sets `pendingOnlineChange`, surfacing **"Hot Reload"**. ⚠️ LD auto-declare can add a variable during live edit — allowed in the editor, refused at Hot Reload.
**Sim while connected:** local sim and a remote PLC coexist, and **Build & Send is NOT disabled during a run** — it `window.confirm`s instead, since it recompiles + RESTARTS (state lost).

⚠️ **FB outputs have two representations and the overlay handles both:** the local sim reads the struct via DWARF as an object at `prog_X_blink`; target/hot-swap streams FLAT keys `prog_X_<var>.<pin>` by SHM offset (each scalar OUTPUT pin is its own slot). Needs a re-Build&Send.

⚠️ **A live badge is drawn when a VALUE EXISTS — not only when the pin carries a variable** (`showInBadge`/`showOutBadge`, RungContainer). The old rule showed an unassigned pin's value only while the canvas was READ-ONLY, i.e. never during a hot-swap sim (which allows online editing), so every block's I/O looked dead although the shadow fields were streaming correctly — the symptom was "no debug values on block outputs". In an editable live view the badge sits ABOVE the input (`*BadgeAbove`) instead of replacing it: covering an empty field swallows the clicks needed to wire a freshly dropped block.

**Rung geometry ⚠️:** `MIDDLE_Y` is **FIXED at `MIN_RUNG_HEIGHT/2`** — never proportional to the dynamic `RUNG_HEIGHT`, or the rail dots move as a rung grows. The `[10,10]` grid can't land a contact's handle on `MIDDLE_Y`, so `powerHandleOffsetY(nodeId)` measures it from the DOM and drag/drop snap to `MIDDLE_Y - offset`. ⚠️ **Agent-authored blocks never take the drop path**, so they inline the same arithmetic (`LD_*` in `agentTools.js`) — **if `RungContainer` geometry changes, these follow**; `insertBlock`/`addBlockToRung` **return the block id** for the snap.

⚠️ **Rebuilt nodes MUST carry `width`/`height` from `prevNodes`** (`carryDimensions`): ReactFlow paints `visibility:hidden` on any node it considers unmeasured, and `createNodeInternals` re-derives dimensions from the incoming object (only `handleBounds` is inherited) — so a rebuild un-measures every node and recovery depends on a ResizeObserver notification for an element whose size did NOT change, which a browser may skip. FB blocks and the power terminals stayed invisible while still in `rung.blocks`; a contact survived only because selecting it thickens its border (29→31 px).

**RungContainer performance ⚠️:** never put `liveVariables` in `mapBlocksToNodes` deps (rebuilds every node every 500 ms — use a separate effect touching only `n.data.liveVariables`); `useMemo` `varsByType`/`dtMap`/`allRawVars`; `isValidConnection` resolves handles **by name**, not index.

**Undo/redo:** the project tree covers sidebar structural ops via `undoHistoryRef={past,future}` (cap 50), gated on `getEditorScope()` being SIDEBAR/null. The LD editor keeps `{rungs, variables}` pairs: ⚠️ **every mutation must call `saveHistory(newRungs, newVariables)` with both**, ⚠️ **outside** setState updaters (inside double-counts under StrictMode).

⚠️ **Focus guards:** every global keydown handler (undo/redo, Space-toggle, Ctrl+X, clipboard) must bail on `INPUT`/`TEXTAREA`/`isContentEditable`/inside `.monaco-editor` — a tagName-only check misses the inline ST editor — **and a global Ctrl+C must ALSO bail on `hasTextSelection()`**: selecting text in a plain `<div>` leaves focus on `<body>`, and the handler replaced the selection with a copied POU.

⚠️ **Monaco:** both mounts use **`defaultValue` (uncontrolled)** + a position-preserving sync effect, NOT `value={code}` — the controlled path calls `setValue()` on every parent re-render and jerks the caret to (1,1). The EditorPane effect **skips its first run** so opening a POU doesn't mark the project unsaved.
## The AI agent panel
**[`docs/PLC_AGENT.md`](../docs/PLC_AGENT.md) is the full reference** — architecture, tool reference, ladder DSL, provider matrix, prompt policies, loop hardening. Keep it updated instead of growing this section.

`AiAgentPanel.jsx` is a tool-calling agent ("PLC Agent") that edits the project; config in `localStorage["aiAgentConfig"]`. Three layers: **`ai.go`** (provider-agnostic proxy at `POST /api/host/ai/chat`), **`anthropic_oauth.go`** (Claude subscription sign-in), **`agentTools.js`** (the pure executor `applyToolCall`, never mutating in place).

Cross-cutting rules:
- ⚠️ **`baseUrl` is honored ONLY by `custom`** — one shared config field, so a leftover value redirected every named provider *and* leaked its API key there; `switchProvider` must not carry credentials across providers.
- ⚠️ **The model picker reads a LIVE catalogue** (`POST /api/host/ai/models`); `PROVIDERS[].models` is only the offline fallback — never "fix" a stale picker by editing it.
- ⚠️ **The Model field is a `<select>`, never a free-text combo** (as a combo, filter and selection shared one input so only the current model was reachable); a saved-but-unlisted model is prepended, an empty list falls back to a text input.
- ⚠️ **Anthropic prompt caching:** `buildSystemPrompt` must stay **stable**; volatile project state rides the separate `context` field, appended AFTER the `cache_control` breakpoints (caching is a byte-exact prefix match). `context` also carries the **run-state line** — the ONLY thing telling the model a program is running, so without it a weak model invents "nothing is running" while a target streams. Live reads use `liveRef`/`liveBufRef`, never `runTurn`'s frozen `liveVariables` closure.
- ⚠️ **`parseArgs` MUST return a copy** — the loop enriches args in place (`__library`, `__live`, …) and once wrote a 47 KB catalog into history twice in one turn.
- ⚠️ **Never present a locally recovered tool call to a provider** — text-mining recovery runs only for `ollama`/`custom`, tags calls `_synth: true`, and `providerSafeMessages` strips them (rewriting their `tool` results too, since an orphaned `tool` message is a 400).
- ⚠️ **A dead turn (no text, no tool calls) must never reach the transcript** — it serialized as an empty text block and 400'd *every* later message, bricking the conversation.
- ⚠️ **Every tool call must be paired with a result** — `providerSafeMessages` pass 1 inserts a "NOT EXECUTED" stub for a missing one and drops orphan `tool` messages; tool results are written into `convoRef` BEFORE the next turn. Stop / cancel / the turn limit used to leave a dangling `tool_use` that 400'd every later request, persisted across reloads.
- ⚠️ **App callbacks are read through refs** (`onHotSwapRef`, `onAppliedRef`) and the committed tree is PASSED (`onHotSwap(touched, {structure})`) — `runTurn`'s closure is stale and App's state hasn't re-rendered, so hot reload compiled the PRE-commit tree, bypassed the layout check and logged "applied".
- ⚠️ **MANUAL mode defers `write_file` to Approve** (dry run only checks permission/path), and an approval REPLAYS the steps on the current tree when the user edited meanwhile (refusing if one no longer applies); AUTO mode restarts from the user's tree if it changed since the last commit (`preCommitPsRef`).
- ⚠️ **Truncation is the other dead-turn source:** `defaultMaxTokens` is **32000** (thinking tokens bill against it); a max_tokens/length finish **discards the turn and fails loudly** — a tool call cut mid-arguments comes back partially parsed and looks well-formed.
- ⚠️ **`aiToolCall.Extra` round-trips the provider's opaque per-call blob verbatim** (Gemini's `thought_signature`) — never parse or synthesize it.
- ⚠️ **Hardware blocks reach the agent ONLY through `args.__hardware`** (`getBoardBlockDefs(board, ifaceConfig)` — the shared source the Toolbox and VariableManager also use): no XML declares GPIO/PWM/ADC/CAN, and the transpiler registers them for the duration of ONE transpile, so a catalog built from `libraryData` alone made the agent insist the board has no I/O at all. They are EN/ENO blocks — `powerPins(…, isHardware)` mirrors `halBlockMeta`, since the generic first-BOOL fallback picks `GPIO_Write.VALUE` — and the board's list rides `<project-context>`, never the cached system prompt. ⚠️ **A power-wired one must carry `data.executionControl: true`**: RungContainer strips EN/ENO from a board block's pin body, so without the flag those handles don't exist, ReactFlow drops both edges and the rung LOOKS like an unconnected island (codegen was correct all along); the flag also makes `LD_FB_Y`'s "trigger is the first pin row" true.
- ⚠️ **No compile/build tool, deliberately** — `check_compile` made every edit pay clang's cold load.
- ⚠️ **Local file access is permission-gated and OFF by default** (📁 button → one root folder, read or read+write): `FS_TOOL_DEFS`/`FS_WRITE_TOOL_DEFS` stay OUT of `TOOL_DEFS` and are appended in `runTurn` only while granted — a model that can SEE a tool it may not use retries it and blames the project. `resolveInRoot` (segment-prefix containment) is the whole guard; the host agent's file endpoints don't sandbox.
- ⚠️ **A clarifying question is the `ask_user` TOOL, never prose** (a text-only turn ends the loop); it is intercepted before the executor and must return a result for **every** `tool_call_id` in the turn.
- ⚠️ **Stop is generation-based** (`runGenRef`), not just `abort()` — the loop recurses between turns with no request in flight. The Stop control lives in the **input bar**, and `resolvePending` must re-arm the run state.
- ⚠️ **Types go through `resolveVarType`** — a scalar, a standard FB type (`STANDARD_FB_TYPES` = the transpiler's exported `FB_OUTPUTS` minus `EN`-trigger inline ops), an existing data-type/POU name, or once-only `ARRAY[m..n] OF TYPE`.
- ⚠️ **`set_ladder` validates contact/coil targets and fails loudly** (valid IEC name, BOOL if declared, unknown `subType` errors instead of falling back, comparisons route to ST) — a bad rung must never compile into a plausible wrong program. `add_variable` refuses a local that shadows a global.
- ⚠️ **On an SCL POU each authoring tool owns ONLY its own language's rungs**, or one deletes the other's work.
- ⚠️ **Wiring tables (`FB_TRIGGER_PIN`, `FB_Q_OUTPUT`, `powerPins()`) are exported from the transpiler — never hand-copy them.** Run **`experiments/agent-check/gate.sh`** after touching the ladder DSL or the LD path.
## Board support (adding an SBC)
Boards group into **display families** (`BOARD_FAMILIES`) and, separately, **HAL families** (by ID prefix, deciding HAL header, triple, device paths, server binary).

HAL families: `..._RPI` (Pi + all generic-Linux SBCs, aarch64) · `..._BB` (BeagleBone; `bb_ai64` aarch64, rest armv7) · `..._JETSON` (aarch64), each with its own `kronhal_*.h`.
**Generic-Linux SBCs reuse the RPi HAL** (standard gpiod, `/dev/i2c-*`, `/dev/spidev*`, `/dev/tty*`): `opi_`, `radxa_`, `odroid_`, `bpi_`, `libre_`, `pine_` — 12 aarch64 boards with their own display family but mapping to `HAL_BOARD_FAMILY_RPI`, so no new HAL, triple or server binary. ⚠️ They inherit the RPi `BOARD_PORT_DETAILS`, functional defaults that differ per SoC, so users override per port.

**Board-less projects — the `Generic Linux` family** (`generic_linux_x64` / `_arm64` / `_armv7`) targets any Linux box (industrial PC, VM, unlisted SBC). It maps to `HAL_BOARD_FAMILY_RPI` and emits C identical to an RPi board's.
- ⚠️ **The arch lives in the ID and BOTH switches must spell it out:** `compileForTarget` defaults unknown ids to **aarch64** while `serverBinaryForBoard` defaults them to **amd64**, so a single "generic_linux" id would cross-build one arch and deploy the server for another.
- ⚠️ **No `pinout`/`pinLayout` and no GPIO/PWM/ADC — deliberately.** The header is unknown, so a pin diagram (and the RPi-numbered GPIO of `resources/krontek-include/CLAUDE.md`) would be a lie; `interfaces`/`BOARD_CHANNELS` carry only device-node peripherals (I2C/SPI/UART/CAN/USB), each overridable per port. BoardConfigPage renders a diagram only for a known `pinLayout`, so the panel is simply empty.

⚠️ **Device-node overrides (UART+I2C+USB) reach the HAL** via `buildRuntimePortHelpers`, emitting `#define KRON_UART<n>/KRON_I2C<n>/KRON_USB<n>` from `content.deviceInterfaceConfig` *before* `kron_hal.h`; SPI has none.
- ⚠️ **The USB override is gated on the port being ENABLED — UART/I2C are not.** The input renders only for an enabled port, and there is **no `KRON_USB_PortEnabled` gate in the HAL**, so this emission guard is the only thing stopping an invisible stale path from redirecting a channel.
- ⚠️ **USB channel → default path is NOT `USB<n>` → `/dev/ttyUSB<n>`:** Jetson/RPi map USB0/1 → `ttyUSB0/1`, **USB2/3 → `/dev/ttyACM0/1`**, USB4 → `ttyUSB2`. Prefer a stable `/dev/serial/by-id/…` name — `ttyUSB<n>` numbering moves across reboots, and `_usb_open` doesn't cache a failed open so a late udev symlink self-heals.
- The I2C **clock-Hz field is decorative** (Linux i2c-dev can't change bus speed at runtime); only the SPI clock is real.

**Checklist — aarch64 SBC in an existing family:** add the board object to a `BOARD_FAMILIES` family (reusing `GENERIC_40PIN_HEADER`), then add `BOARD_CHANNELS[id]` — ⚠️ **a key here MINTS BLOCKS in the toolbox**, so omit `CAN`/`ADC` rather than guessing (`jetson_nano` claimed `CAN:1`, but Tegra X1 has none). Nothing else if the prefix already maps to a HAL family.
**A new vendor prefix** also goes in all three `getBoardFamilyDefine`, in `serverBinaryForBoard`'s aarch64 list, in `LINUX_BOARD_FAMILIES` (only if a genuinely new HAL family) and in `boardIcon()`. **A new HAL family** additionally needs `kronhal_<family>.h`, a `compile.go` triple case, and a server binary.

### Stub blocks

- ⚠️ **A stub-bodied block carries a `note` in `BLOCK_NOTES` (`boardLibraryBlocks.js`) → `warning` in the agent's catalog.** `PCM_*` (all families) and `Grove_*` (bb_green) are empty stubs and `PCM_Output` even sets `OK = EN`, so a human at least sees an unfinished block while the agent had no cue at all. Delete an entry when its `_Call` lands.

## Addressed variables (IEC addresses)

**Addressed variables & REST.** An IEC address in the "Address" column exposes the variable over REST. Prefix per type (`IEC_TYPE_PREFIX`, `utils/iecAddress.js`): BOOL→`%MX{byte}.{bit}`, BYTE/SINT/USINT→`%MB`, INT/UINT/WORD→`%MW`, DINT/UDINT/DWORD/REAL→`%MD`, 64-bit + TIME/LTIME→`%ML`. The API password is salted into `variable_table.json`; empty = API disabled.
⚠️ **INVARIANT — the prefix MUST agree with the type; nothing downstream re-derives it.** An address is a width *claim* but only a label to the runtime (which addresses by `Offset`/`Size` from the TYPE), so a mismatch **never fails anywhere** — it surfaces when SCADA reads a word where a bit was published. `iecAddress.js` is the single rule, applied by **VariableManager** (⚠️ type + address must land in **ONE** update, hence the object patch in both `handleUpdateVar`s), **`agentTools`** (address resolved *after* the type), and **the transpiler gate** in `transpileToC` — a hard `throw`, the only one covering hand-edited XML.
⚠️ **Only elementary types can be addressed** — debugDefaults expansion hands the SAME address to every element, so an addressed `ARRAY[0..9] OF INT` publishes ten variables claiming one location. Keep `IEC_TYPE_PREFIX` in sync with the four transpiler tables (root `CLAUDE.md`). **Deliberate gaps:** addresses on FB/FUNCTION locals do nothing; duplicates are not a build error.

## EtherCAT editor (Slave / ESI)

⚠️ **An SDO Init row's WIDTH belongs to the OBJECT, never to the user** (`resolveSdoByteSize`): the slave's own ESI `BitLen` wins, else `CIA402_SDO_SIZES`, else the stored value for a vendor object nobody can size — and the TRANSPILER re-resolves it at emit time (loudly), because a project saved before this still carries the old value. The editor shows it read-only, offering the manual select only for an unsizable object. A mis-sized write is ABORTED by the drive and the failure chain names nothing: `PO2SO SDO failed`, PreOP→SafeOP fails, `Could not reach OP state`, slave state `0x00`, endless recovery — project looking perfectly healthy. Cost an afternoon on a real D5V120E with `0x6060` (Modes of operation, **INT8**) stored as 2, from a free `<select>` that defaulted to 2. ⚠️ An ESI lists one object in several **alternative** PDOs (`0x6040` in 0x1600/0x1601/0x1602), which reads as a duplicated import — selecting two is the `duplicate-object` hard error, so the editor dims the alternatives and names the PDO that already has it.
- ⚠️ **PDO variable NAMES have ONE generator: `utils/ecNaming.js`** (`buildEcVarNames`/`findEcIssues`), used by the Slave editor AND the transpiler. They used to be computed twice with a collision **counter** over different scopes (per slave vs per bus), so one collision made the editor declare `ec_X_Status` while codegen emitted `ec_X_Status_2` — the global then got a real PlcState/SHM slot instead of the GPI macro and read a constant zero. The scheme is **counter-free**: a contested base gets `_<pos>_<idx>_<sub>` appended to **every** claimant, so the result is order-independent. Same file holds the hard gates (`duplicate-object`, `excluded-pdo`, `duplicate-name`, `invalid-name`) and the `KRON_EC_MAX_*` mirrors; a custom IEC Var Name is sanitized on BOTH sides.
- ⚠️ **ESI `<Data>` is LITTLE-ENDIAN** (`EsiParser.parseStartupSdos`) — `parseInt(hex,16)` byte-swapped every imported SDO into a plausible wrong number. Exclusivity is `<Exclude>` ONLY: a shared `Sm` is not it (an EL1008 puts 8 coexisting TxPdos on Sm 3). `txt()` reads **direct children** — via `querySelector` a `<TxPdo>` without a `<Name>` took the first Entry's. InitCmds are filtered to **PS**.

## Clipboard

**Clipboard (`kronClipboard.js`):** cross-tab copy/paste over `navigator.clipboard` with an in-process fallback; payloads tagged `CLIP_KIND`; handlers scope-gated by `editorScope.js`.
- ⚠️ **The LD editor root MUST use `onMouseDownCapture`** — ReactFlow's node drag `stopPropagation`s a bubble-phase mousedown, so the scope would stay SIDEBAR and Ctrl+C would copy the whole program.
- ⚠️ **Never call `navigator.clipboard.readText()` while OPENING a menu** — Firefox/Safari answer with a native "Paste" chip that hides the app menu until dismissed. Menu builders use `peekClipboard()`/`refreshClipboard()`; **cross-window sync rides a localStorage mirror**, so same-origin windows see each other permission-free.
- **Paste naming differs by kind on purpose:** POUs / data types / local variables keep their name and append `_copy{n}` on collision, but a **global-variable SET** (and globals bundled with a POU) **merges by name** — a same-named global is skipped and addresses dropped, because merging into another project is the point.
