## The transpiler (ST/LD → C)
`src/services/CTranspilerService.js`:
```js
transpileToC(projectStructure, standardHeaders, boardId, simMode, buses=[], busConfigs={})
  → transpilePOUSource(pou, globalVarNames, stdFunctions, interfaceConfig)
    → transpileSTLogics(...) | transpileLDLogics(rungs, blockType, parent, category, varMap)
```
All three call sites in `App.jsx` pass `buses`/`busConfigs` as args 5–6.
**Scoping:** globals → `S->${name}` (no prefix, matched against `globalVarNames[]`); program locals → `S->prog_NAME_${name}`; FB-instance locals → `instance->${name}`. `varMap` is built in `transpilePOUSource`.

⚠️ **Every ST EXPRESSION goes through `stExpr.js`** (tokenizer → Pratt parser → typer → C emitter); statements (IF/CASE/FOR/…, `;`/`:=` splitting) stay line-based but hand every condition, RHS, argument, selector, bound and index to it. The typer decides what the old regex passes guessed: AND/OR/XOR/NOT are **logical on BOOL, bitwise on ANY_INT/ANY_BIT** (NOT masked to the width); integer `/`/MOD → `KRON_IDIV`/`KRON_IMOD` (÷0 and `INT_MIN/-1` → 0 — a raw `/` is SIGFPE on x86_64); `**`/EXPT → `pow`; SHL/SHR/ROL/ROR inline, width-aware, count ≥ width → 0; MIN/MAX/LIMIT/SEL/MUX typed, each argument evaluated once; mixed signed/unsigned and int/real compares get an explicit common type. IEC precedence (AND > XOR > OR) differs from C's (`^` above `&&`) — the emitter parenthesises everything. ⚠️ **A type no table describes is UNKNOWN (null) → plain C / `KRON_*_U` macros — never guess one** (a BOOL guess turns `inst.ErrorID = 5` into a type error). Unknown names, non-BOOL conditions, chained compares, `:=` inside an expression are LOUD transpiler errors (`ST PROGRAM X, line N: …`).
⚠️ **The LD path does NOT use the parser** — LD operands go through `resolveVal`, and LD math/compare/MIN/MAX/LIMIT/SEL emit plain typed C (never kroncompare's `_Generic` macros, which dispatch on ONE argument). Its type lookup is `cSymTypeMap`, ⚠️ **keyed by exactly what `resolveVal` returns** (`S->prog_P_x`, `instance->x`, `(*p)`) — a key mismatch silently sent every REAL ADD down the int32 struct path.
⚠️ **Names:** declared types are canonicalised once (`canonicalizeProjectTypes`: `ton`→`TON`, `int`→`INT`), then compared exactly; C keywords/`S`/`errno` as names emit as `iec_<name>` via `cIdent` (live/retain keys keep the IEC name, only `c_symbol` changes); every numeric literal goes through `iecNumberToC` — IEC `014` is decimal, C reads it as octal.

**ST line handling (order matters):**
- ⚠️ **Comments and strings have ONE scanner, `stripIecComments`** (nested `(* (* *) *)`, `//`, `/* */`, `'…'`/`"…"` with `$` escapes) — used by the transpiler, the validator and `countStringConvCalls`; never strip comments with a regex (`'http://x'` lost the line tail, `'(* x *)'` became empty). It runs BEFORE keyword normalization, else a keyword inside a comment injects a newline that leaks the tail into C.
- ⚠️ **Continuation merge is bidirectional:** a line ending in an operator/`,`/`(` merges forward (`:=` excluded) *and* a line starting with a binary operator merges backward — excluding bare CASE labels and lines ending mid-block. Without the look-back, `x := a * 128\n + b / 2;` lost its second term; test leading-`+`, leading-`AND`, a `-1:` label.
- ⚠️ **String literals become `\x0e<idx>\x0f` placeholders** before keyword normalization (`'go THEN stop'` was split) — bare digits would let the restore corrupt numeric literals.
- ⚠️ **EXIT with a CASE between it and its loop is `goto __exit_N`** (C `break` only leaves the switch); CONTINUE → `continue`, `REPEAT…UNTIL c END_REPEAT` → `do{}while(!(c))`. **FOR runs on a hidden `int64_t` counter** — iterating the control variable never ends when `end` is its type's max (USINT 255) or counts an unsigned down to 0. Labels and FOR counters share one per-POU counter (`stOpts.labelSeq`).
- **FUNCTION VAR_IN_OUT is a pointer parameter** (`(*p)` in the body, `&(arg)` at the call); FB VAR_IN_OUT is copy-in + copy-back. FB-local and instance initial values (`t : TON := (PT := T#1s)`) are emitted recursively by `fbInstanceInitLines`.

⚠️ **The task interval bounds every timer:** a self-resetting TON needs 2 extra scans per half-cycle, so the observed half-period is `PT + 2 × task_interval` (PT=1s on a `T#1s` task toggles every 3.00 s). Keep the interval an order of magnitude under the shortest measured time.
⚠️ **TIME/LTIME are `int64_t` MICROseconds** end-to-end (`kronstandard.h`, `mapIECtoTimeUs` → `us_tick` → `TON_Call`) — 8 bytes, `%ML`; uint32 ended at ~71.6 min. Elapsed time is modular-unsigned then signed; a negative one re-anchors (retained StartTime from a previous boot).
⚠️ **Task assignment is STRICT:** a program runs only if explicitly assigned to a task — no fallback. Unassigned code is generated but never called (the transpiler warns, `handleToggleSimulation` surfaces it); zero tasks → nothing runs.

**LD:** `rung.blocks[i].type / data.subType / data.values`; `rung.connections[i].sourcePin/targetPin` (`out`/`in`, or `out_0`/`in_1` for FBs). Globals never get `prog_`. FB trigger pin `in_0`/`in` = power flow, `in_1`+ = separate assignments; SR trigger → `.S1`, RS → `.S`. Constants: `FB_TRIGGER_PIN`, `FB_Q_OUTPUT`, `FB_INPUTS`, `FB_OUTPUTS`, `FB_INPUT_TYPES`.
- **LIMIT/MUX emit by argument NAME, not position** (a 2-input `MUX` becomes a ternary).
- ⚠️ **Legacy per-channel HAL blocks** (`I2C0_Read`, `SPI1_Transfer`, …) left the Toolbox for `COMM_PROTO_BLOCKS`, but saved projects still carry them: `transpileToC` registers them as EN/ENO blocks from the pin list each saved block carries — unregistered, EN was never set (the `_Call` silently did nothing) and power flow read a nonexistent `.Q`.
- **Rising/Falling contacts and coils have real edge memory** — a persistent BOOL per block, so they do affect `plc_state_layout_hash`.
- **TIME pins:** only `T#…` literals go through `mapIECtoTimeUs` (**throws** on an unparseable literal); variables pass through `resolveVal`. `0b/0o/16#` parse in `resolveVal`; malformed tokens return null rather than leaking into C.

⚠️ **Every LD block's data output gets a PlcState debug field** (`prog_<P>_out_<inst>_<PIN>`, `collectShadowVars`) — **inline blocks included** (ADD/EQ/BAND/`X_TO_Y`/MIN/MAX/SEL/MUX/LIMIT): stateless, their result otherwise existed only inside the C expression it fed, so an unassigned OUT/Q pin was unobservable — and the shadow write is ALSO what forces the expression to be emitted when no variable and no wire consumes it. ⚠️ The pre-scan and the emitter must name fields by the SAME rule (`data.instanceName || type`; the editor mints a unique instance per block and the UI reads that exact key). An inline numeric OUT is held as **LREAL** — int-vs-float is chosen at EMIT time (`useReal`) and a double carries int32 exactly, so one field type can never truncate; ENO is skipped (it IS the rung's power flow), a **text operand skips the write** (`char *` into a numeric field), and `X_TO_STRING` **aliases** the debug key onto its existing `strConvSymbol` buffer (a second field would be a stray `char[64]`, and C has no assignment to an array), emitting `(void)(…)` when nothing else consumes it.

**Arrays & SHM:** a C array is sized **`[max+1]`** (not `[max-min+1]`) so raw IEC indices stay valid with lower bound > 0; ⚠️ negative lower bounds and `upper < lower` are rejected. Data grows from 0 (⚠️ **naturally aligned**, `a = min(size, 8)` — what makes the runtime's/readers' 1/2/4/8-byte copies atomic, 64-bit on armv7 included), force flags from `FORCE_FLAGS_BASE` (32768), the force mailbox at 61440, segment 65536 (layout v2, `server/RING_FORMAT.md`); ⚠️ the transpiler **throws** if a region overruns. Forced values are re-injected from `PlcState.__plc_fv`, never from the data slot (another task's sync may have rewritten it). Struct-member debug offsets use **natural C alignment**.
⚠️ **exec-time is MICROseconds** (`__exec_us_<prog>`); changing a unit means grepping the FORMATTERS too — `fmtExecNs` survived the ns→µs migration.

**Gates:** `experiments/transpiler-check/compile-gate.sh` (**run after transpiler changes**) and `experiments/agent-check/gate.sh` (`src/CLAUDE.md`) — ⚠️ both are gitignored, absent from a fresh clone; without them, bundle the transpiler with `esbuild --loader:.tpl=text` and compile its output with `toolchains/bin/clang -fsyntax-only`.

## Motion & EtherCAT codegen

**Motion:** the `MOTION_FB_AXIS_PARAM` set — every `MC_*` block calls `MC_xxx_Call(&inst, &axisVar)`; `Axis` (AXIS_REF) is not a struct field (skipped in value assignment, null-init and shadow vars). All `motion.xml` blocks list `Axis` first.
- ⚠️ **The axis engine runs in the IO_Bus thread at the BUS cycle** (`__kron_axis_step()`, step 2 of `plc_task_IO_Bus`), and **`dt` is that bus's `cycle_us`** — taken from the bus carrying the axis, so a second fieldbus brings its own. ⚠️ **Thread and dt are ONE decision:** the core integrates exactly one `dt` per call, so a 500 µs `dt` called from a 10 ms task runs the machine 20× slow. It used to live in the logic task with `dt` = that task's interval; measured against the real archive, a 10 ms `dt` makes a jerk-limited move **hunt around the target for ever** (40 set-velocity sign flips, ±31 500 counts, `Done` never set, DiscreteMotion never left) while the same move at 500 µs lands in one approach.
- ⚠️ **`__kron_axis_mu` (one lock, all axes, `PTHREAD_PRIO_INHERIT`) is what makes that legal** and EVERY entry point takes it: the engine step, and every `MC_*_Call` emitted into a logic task — **spanning the pin writes too**, since `KronAxis_Submit` stores a pointer to a request living INSIDE the FB instance into `AXIS_REF.Active/Buffer[]` with no handshake of its own (`kron_axis.c` dropped `cmd_Seq`/`sts_AckSeq`, and the archive is prebuilt). It also covers the READ side — `AXIS_REF.ActualPosition` & co. are 8-byte doubles armv7 cannot load atomically. Axis init is locked too: under hot-swap the bus thread is already running when `PLC_Init` reaches it.
- ⚠️ **Non-Linux has no IO_Bus thread**, so there the engine stays in the owning task under `#if !defined(__linux__)` with `dt` = task interval (sim only; those builds are `KRON_EC_SIM`). The >1-motion-task warning now only matters for that path.
- ⚠️ **`kronmotion.h` is the source of truth for SIX places** — `FB_INPUTS`+`FB_OUTPUTS` (together they must equal the struct's non-`_` fields), `FB_TRIGGER_PIN`/`FB_Q_OUTPUT`, `MOTION_FB_AXIS_PARAM`, `motion.xml`, and `libraryTree.js` (omitted → never in the Toolbox). A pin named in a table but absent from the struct is a **compile** error, the reverse is a silently dead pin.
- ⚠️ **`MOTION_FB_OUTPUT_TYPES` is mandatory for every non-BOOL MC_ output** — `getOutputPinType` keys off pin NAMES and falls through to BOOL, so `Position`/`Velocity`/`Torque`/`Value`/`CoveredDistance` (LREAL) and `ErrorID`/`AxisErrorID` (WORD) collapse to one bit without it.
- ⚠️ **`AXIS_REF_DEBUG_FIELDS` (transpiler) and `AXIS_REF_BUILTIN` (VariableManager) hand-mirror the struct**; offsets are x86_64 `offsetof` for the sim's `/proc/mem` reader, and a name IS the C member path (`Set.Position`). Re-verify with a probe after any AXIS_REF edit.
**Config generation:** `generateEtherCATConfig(buses, busConfigs)` → `KRON_EC_Config` init C; `kron_ec_init`/`kron_ec_close` in PLC_Init/Cleanup, and per task `kron_ec_pdo_read` before `plc_shm_pull`, `kron_ec_pdo_write` after `plc_shm_sync`. Files: `EtherCATEditor.jsx` + `deviceCodegen.js`, `SlaveConfigPage.jsx` + `EsiLibraryService.js`.
- ⚠️ **Axis init uses `S->${axisName}`** (globals are PlcState fields).
- ⚠️ **IO_Bus carries inputs and outputs differently:** inputs double-buffered (`__gpi_buf[2]`/`__gpi_snap`), outputs through the single **`__gpi_out`** written by the logic. Both through the double buffer meant `*back = __gpi_hw` overwrote outputs the logic wrote after the snapshot — an output pulse could never reach the slave. The axis **write** bridge runs BEFORE `kron_ec_pdo_write` (it ran after, costing every axis command one bus cycle), the read bridge after `pdo_read`.
- ⚠️ **`EC_FB_OUTPUT_TYPES` is mandatory** for `ErrorID`/`State`/`SlaveCount`/`Value` (same trap as `MOTION_FB_OUTPUT_TYPES`), and **`blockConfig` in RungContainer must match `ethercat.xml`** — it carried six phantom names (`EC_Init`, `EC_ReadPDO`, `EC_SlaveStatus`, …) that `RungEditorNew` accepted as types, and `VariableManager` types live output pins from it. An `EC_*` block with no bus, or `axisRef.enabled` with no `AXIS_REF` global, are both hard transpiler errors now (clang said `undeclared identifier '__ec_cfg'` / `no member named 'Axis1'`).
- ⚠️ **PDO variable names are excluded from the `S->` mapping** — the transpiler emits `#define ec_X (__gpi_snap->_pi_ec_X)`, so they stay bare identifiers with no `PlcState` field and no SHM slot; mapping them would expand to `S->(__gpi_snap->…)`, a syntax error.
- ⚠️ **Motion IS hot-swap-trampolined now** (the engine lives in the bus thread, i.e. in the host): `AXIS_REF` is a PlcState field whose offset only the module knows, so the OPTIONAL ABI export **`plc_axis_ptr(i)`** is resolved by host.c **after `bind()`** and fed to the generated `__hs_axis_bind()`, which caches the pointers in `__hs_axis[]`. Re-done on every swap. Both halves optional ⇒ a no-axis project and an older `logic.so` just skip it. The trajectory core therefore sits in the HOST and is **not** swappable — an axis/bus edit needs a host rebuild, which `ioEcSignature` already forces.

## Library blocks (XML ↔ C)

**Blocks are declared in `public/libraries/*.xml`** (`<block type>` + `<inputs>`/`<outputs>` `<pin name type [trigger]>`, grouped in `<category>`), arranged for the Toolbox by `libraryTree.js`.

⚠️ **An XML block with no C implementation is a PHANTOM — draggable, then unbuildable**, dying at **compile** time with `unknown type name 'X'`; nothing checks the pairing. **Still phantom:** `Log_Data`, `PID_Compact`, `Filter_LowPass`, `Modbus_Master`, `MQTT_Client`, `TSEND`, `TRCV`, `Get_Alarm_State`, `Read_Hardware_ID`. Comparison/math/bitwise/trig/`X_TO_Y` legitimately have no `_Call` (emitted inline).

**Implementing one: `kronsystem.h` is the pattern** — other blocks live in a prebuilt `libkron*.a` and `CLAUDE.md` forbids generating `.a`s, so this header holds `static inline` bodies compiled into `plc.c`/`logic.so`. ⚠️ It is the ONE file under `krontek-include/` besides `HAL/` that is **git-tracked**. It carries **27 blocks**: RTC/calendar, scheduling, diagnostics, Linux-only host health (temp/load/disk, else `ERR_ID=1`), TIME arithmetic, signal shaping, and the sysfs readers `Read_Sys_File` / `Read_Hwmon` (which finds a device **by `name`**, since the `hwmonN` index is probe-order and moves across boots). ⚠️ **The readers only READ** — they publish the file's text on a STRING `VALUE` and leave meaning to the program (compare, or convert); parsing inside them would force a number onto files that hold a word. **Five** things must line up — the XML and a `libraryTree.js` entry (else it never reaches the Toolbox), plus:
1. **The header** — `typedef struct {…} X;` + `static inline void X_Call(X *inst)`; `transpileToC` scans every served `kron*.h` for that shape (**comments included**) and auto-registers it. ⚠️ The parameter list — **which contains the struct type name** — must not hold the literal `TIME`, or the block is taken for a timer and called as `_Call(&inst, us_tick)`. The test is **case-SENSITIVE**: `Read_System_Time`/`Add_T` pass, `TIME_SWITCH`/`ADD_TIME` would not compile.
2. **`FB_TRIGGER_PIN`, `FB_Q_OUTPUT`, `FB_OUTPUTS`, `FB_INPUTS`** + **`FB_INPUT_TYPES`** for non-trigger inputs, pin names exactly as the XML declares.
3. **`SYSTEM_FB_TYPES`** if the trigger pin is `EN` — else `isInlineMathType` calls it stateless inline math: no `PlcState` field, no instance, no codegen branch to land in. Same reason TIME arithmetic is FBs, not inline (that branch dispatches only via `KRON_FN`/`BITWISE_OP`/`MATH_FB_BLOCKS`). ⚠️ Those also avoid the `X_TO_Y` name shape, which `transformExpr` rewrites to `KRON_<src>_TO_<dst>` — resolvable only inside the archive; hence `T_To_Ms`, not `TIME_TO_DINT`.
4. **`SYSTEM_FB_OUTPUT_TYPES`** for EVERY output pin: the generic rules key off pin NAMES and fall through to **BOOL**, so an unlisted `Year`/`TEMP`/`OUT` is silently wrong. (`Read_System_Time.TIME` is a **DINT**, ms since LOCAL midnight — epoch ms wouldn't fit — not an IEC duration.)

⚠️ **STRING is a VALUE: `kron_string_t` = `char[64]`** (63 + NUL, `KRON_STRING_LEN` = `KRON_SYS_TEXT_LEN`, `_Static_assert`ed) for globals, locals, FB/UDT members and arrays — a `char *` field retained a pointer from the previous process and dangled into a `dlclose`d `logic_N.so` after a swap. ⚠️ **Every `:=` to STRING storage is `KRON_STRSET`** (bounded, NUL-terminating, never splits a UTF-8 sequence), whose `_Generic` refuses a non-array target at compile time; `a := b` used to alias. A STRING FUNCTION takes `kron_string_t *__res` first and every call site owns a function-scope `__sretN` (a shared buffer made `F(a) = F(b)` compare one result with itself). ⚠️ **Standard-block STRING pins stay `const char *`** with **no writable input shadow var** — re-pointed every scan, which keeps them valid across a swap; hence a standard block's STRING pin in an instance initialiser is refused (set once, it would dangle).
⚠️ **STRING pins — quoting is OPTIONAL and a bare word is TEXT.** Quoted `'…'`/`"…"` is always text; a bare word resolves to a variable **only if one is declared**, else it is text too — so a path needs no quotes and `NAME := pwmfan` means the word, not an invented variable. ⚠️ **Quotes are DELIMITERS everywhere, including `initialValue`** (`formatVarInitial` once emitted `"'/sys/…/'"`, unopenable) — one decode/escape pair owns this (`unquoteIecString`/`iecStringToC`), and `collectUndeclaredPinVars` plus the agent's `set_ladder` hint collector must both SKIP string pins or they mint a BOOL/empty STRING behind the user's back. ⚠️ **STRING IS a live value, read-only, via a fixed 64-byte NUL-padded slot** (`STRING_SHM_BYTES`, matching `KRON_SYS_TEXT_LEN`). `plc_shm_sync` copies the characters (bounded loop) and **ignores the force flag**, while `plc_shm_pull` skips text: STRING writes are refused in KronServer's `encodeValue`, the mailbox, `writeHotSwapVariable` and the UI. ⚠️ **Both copies of the sync/pull codegen now come from `shmSyncLine`/`shmPullLine`** (the per-task twins live in `generateMainLoop`, which only receives `shmEntries`, hence `isString` on the entry). The legacy `/proc/mem` sim reads the text in place (the field IS the text now). STRING stays out of `IEC_TYPE_PREFIX` (unaddressable, so never in the capture ring) and out of `IEC_CAST_C` (a cast to text is meaningless). `VarString` is KronServer's only variable-width type, so its `Size` is validated by range, not against `typeSizeMap`.

⚠️ **`=`/`<>` on STRING are LOWERED to `__kron_streq`** in both ST and the ladder `EQ`/`NE` blocks — plain C `==` on two `char *` tests ADDRESSES, so equal text in different buffers compares false and nothing warns. `KRON_EQ`'s `_Generic` would pick the numeric overload, and `kroncompare.h` cannot hold the fix (Build Libraries regenerates it; only `kronsystem.h` is tracked), so the **transpiler** decides by operand type. Ordering (`<`, `>`) on text is a hard error, not a silent pointer compare.
⚠️ **`Log_Data` cannot be a printf** — runtime stdout is a diagnostics log (`host-agent/CLAUDE.md`), not a data channel. Publish values as **variables** (SHM → SSE/REST/HMI/ring).
## Retentive (RETAIN) variables
A variable of class **`Retain`** keeps its last value across a runtime restart (IEC warm restart). Everything retainable lives in `PlcState` (`host-agent/CLAUDE.md`), so persistence is a name-keyed snapshot of a subset of its fields to **`retain.dat`** in the runtime's cwd (deploy dir on target, build dir for the sim).

Offered for **globals** (`['Var','Constant','Retain']`) and **program locals** (`['Local','Temp','Retain']`), including an **FB instance** in a program (the whole struct is one blob, so a `CTU` keeps `CV`). ❌ Deliberately absent inside an FB/function — those aren't `PlcState` fields, so it would be a silent no-op; retain the INSTANCE instead.
- ⚠️ **`VariableManager`'s `showClass` must keep testing for `'Retain'`** — it only fired for POUs with pin classes, making the option unreachable in the two scopes that need it. Sibling trap: the `<select>` falls back to `allowedClasses[0]` when the stored class isn't offered, and a value matching no option renders **blank**.
- ⚠️ **The file is SELF-DESCRIBING and matched BY NAME** (`"KRTN" u16 ver u16 count`, then `{u16 nameLen, name, u32 size, bytes}`). A raw `memcpy(&PlcState)` blob would be shorter and catastrophically wrong — one added variable shifts every offset. Unknown/mismatched records are skipped; a new retained variable keeps its initial.
- ⚠️ **`plc_retain_load()` is emitted LAST in `PLC_Init`**, after `plc_state_init()` writes the initials; the reverse order makes retain a silent no-op. `plc_retain_save()` compares against the last image and skips the disk when unchanged; the write is tmp + `fsync` + rename (⚠️ `MoveFileExA` on Windows).

**Cadence (1 s, `RETAIN_INTERVAL_MS`):** Linux single binary → `plc_retain_thread` + a final flush in `PLC_Cleanup`, reachable because a **SIGTERM handler is installed only when the project has retained variables** (`retainEnabled`), leaving other projects' stop semantics untouched. Windows → the timer wheel in `main()`, periodic flush only. Hot-swap → `retain_thread` in `hotswaphost/host.c`.
- ⚠️ **The logic module must NOT own the flusher thread** (it is `dlclose`d on every swap) — `plc_retain_save` is exported non-static and the host `dlsym`s it **optionally**, re-resolving on every bind.
- ⚠️ **`g_retain_mu` makes that safe:** the flusher runs OUTSIDE the scan barrier, so it may sit in the old module's `plc_retain_save` when thread 0 `dlclose`s it — `do_swap` holds the same mutex across dlclose + re-resolve.
- ⚠️ The retain thread is created **only when there are tasks** — with zero tasks nothing sets `plc_stop`, so an unconditional thread hangs `main()` on its join forever.
- ⚠️ **The agent sets it via a boolean `retain`**, not a free `class` string, and `resolveRetainClass` refuses it outside a global / PROGRAM local — **that single guard also protects FB pin classes** from being rewritten to `Local`.

**Deliberate v1 limits — say these out loud:** the snapshot is async, not scan-boundary, so a >word-sized value on a 32-bit board can be sampled mid-update; the power-cut loss window is up to 1 s (vs per-change writes → flash wear); **Build & Send does NOT reset retained values** and there is **no "clear" button** (force/PULSE-write, or delete `retain.dat`). A record whose size changed (TIME 4→8, STRING 8→64) is skipped once and restarts at its initial. ⚠️ **Not yet run on real hardware.**
