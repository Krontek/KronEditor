## HAL pattern
Every hardware block = **struct + `_Call`**: hardware struct `HAL_UART_Send`, generic struct (in transpiled C) `UART_Send`, channel dispatch `UART0_Send_Call(inst)` → `HAL_UART_Send_Call(inst, 0)`. The runtime header is `krontek-include/HAL/kronhal.h`.

⚠️ **A missing peripheral must FAIL, never fake success** — every `_Call` that can't do its job sets `ERR_ID` and leaves output false/zero (`/* TODO */` bodies returning `DONE = EN` were indistinguishable from a working read). `0`=OK, `1`=absent/invalid channel, `2`=open failed, `3`=I/O error. ADC is IIO on RPI/BB and **`ERR_ID=1` on Jetson**; CAN is SocketCAN (interface must already be up); PRU/PCM/Grove/DI/DO are `ERR_ID=1`.
- ⚠️ **PWM channels are FLATTENED ACROSS pwmchips**, never "the first chip with enough channels" — generic SBCs sharing `kronhal_rpi.h` publish one pwmchip **per PWM cell**, so the old probe matched nothing and PWM was dead on all 12. Chips are collected, **sorted by index** (readdir isn't) and their `npwm` concatenated.
- ⚠️ **`HAL_Init` must set the PWM fd arrays to `-1`** — every check is `fd >= 0`, so a static-zero fd makes `HAL_Cleanup` **close stdin**.
- ⚠️ **KNOWN GAP — GPIO pin numbering is Raspberry-Pi-specific on the 12 generic boards.** `_RPI_PHYS_TO_BCM` maps physical pin → BCM line and `GENERIC_40PIN_HEADER` is literally `RPI_40PIN_HEADER`, but Rockchip/Amlogic numbering differs, so a GPIO block there **silently drives a different pad**; device-node peripherals are unaffected.
- ⚠️ **Jetson `_JETSON_PHYS_TO_LINE` must hold the runtime indices from `gpioinfo /dev/gpiochip0`**, not the `TEGRA234_MAIN_GPIO(port,bit)` DT macro values — on Orin the macro exceeded the chip's line count and every request failed silently.

**Adding/removing a pin on a standard FB — four locations:** the header struct field, the `<pin>` in the XML (LD UI), `FB_INPUTS[type]` (ordered, pre-call assignment), `FB_OUTPUTS[type]` (shadow-var decl + write-back). `FB_OUTPUTS` is the single source of truth — an unlisted pin gets no shadow var and no write-back.

## Motion library (`KronMotion`)

- ⚠️ **`KronMotion` was rewritten around an external trajectory core (2026-09):** `kron_nc.c/.h` are GONE, `AXIS_REF` moved to `kron_axis.h`, every numeric pin is a **`double` (LREAL, never REAL)**, and `kron_axis.h` includes `TrajectoryGenerator.h` from `github.com/fehimkus/OnlineTrajectoryGenerator` — fetched by `externalLibDeps` (`host-agent/CLAUDE.md`), not by KronMotion's CMake.
- ⚠️ **plc.c must NOT define `Kron_PI` / `Kron_HAL`** — `kron_pi.c` (→ `libkron_pi.a`) owns both, so defining them again is `multiple definition` at link. `Kron_HAL` stays NULL: the generated code does the PDO exchange itself and calls the PER-AXIS `KronAxis_ReadInput`/`WriteOutput`, never `KronMotion_ReadInputs/WriteOutputs` (those go through the HAL pointer).
- ⚠️ **`KronAxis_Submit` validates the ACCELERATION of every request, including a stop.** `MC_Stop`/`MC_Halt` fill only Deceleration+Jerk and `MC_Home` only Position, so the effective acceleration falls back to `AXIS_REF.MaxAcceleration` — and the transpiler emits an axis limit ONLY when the Axis tab field is `> 0`. Blank limits therefore make those three FBs return **`ErrorID 1` (MC_ERR_PARAM) for ever** while the pins look perfectly normal. `MC_MoveAbsolute` is unaffected (it supplies its own). Verified by disassembling `libkron_axis.a` and replaying it against the user's config.

## Library header rules

⚠️ **The 18 STRING conversions are `static inline` in `kronconverter.h`, which is GITIGNORED and REGENERATED by Build Libraries** — mirror them into `KrontekLibraries` or the next run deletes them and a fresh clone has none. (`__kron_streq` deliberately stayed in the tracked `kronsystem.h`.) `STRING` is in `_CONV_TYPES`, so the pairs get the normal FB tables, but **both directions are emitted BY NAME, never through the generic C-cast branch** — `(int32_t)(char*)` reads the pointer and `(char*)(int32_t)` invents one. ⚠️ **`x_TO_STRING` needs somewhere to write, and every ownerless answer is wrong** (a static races between task threads, a thread-local pool goes stale, a compound literal dangles after the scan), so the transpiler gives **every call site its own `char[64]` PlcState field** (`strConvSymbol`): ladder sites are named after the block instance, ST sites are numbered against an UPPER BOUND from `countStringConvCalls` (comments and literals are stripped before the rewrite, so it consumes fewer — over-allocating wastes 64 bytes, under-allocating would name a field that does not exist, which is a compile error). One counter per POU, since an SCL program calls `transpileSTLogics` once per ST rung. ⚠️ **Programs only** — a FUNCTION/FB has no PlcState field, and both paths say so loudly.
⚠️ **Three constraints on the bodies** (the header's own comment block is the long form): `us_tick` is **invisible** inside a `kron*.h` — its extern is emitted *after* `customIncludes` — and its origin is platform-dependent, so blocks read `CLOCK_MONOTONIC` via `__kron_mono_us()`; an FB instance is a PlcState field, **zero-filled with no way to set a non-zero initial**, hence the `__primed` bool instead of a `-1` sentinel; a **Retain**ed instance carries a **stale monotonic timestamp** across a restart, so `Hour_Meter` drops gaps > 10 s rather than booking downtime as run time and every polled block discards a cache deadline further away than one poll period (`__kron_sys_cached`) — a future deadline from the previous boot would otherwise freeze it for that whole gap.
