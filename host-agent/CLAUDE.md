## Deploying KronServer to a target

**`deploy_server_to_target`** (`deploy_ssh.go`): SFTP the prebuilt `plc-agent` to `<home>/plc/plc-agent`, install a supervisor (systemd unit, else a restart-on-crash script), start, poll `:7070/status`.
- ⚠️ **The sudo password travels on the SSH session's STDIN only** (`remotePriv`: `sudo -S -p ''`), never on a command line — `echo '<pw>' | sudo -S` put it in `/proc/<pid>/cmdline` and, piped into `crontab -`, wiped root's crontab. One `sudo -S` per session can consume it, so multi-step privileged work is a staged script (run with stdin `/dev/null`); the cron hook filters+appends+reads back INSIDE one script.
- ⚠️ **Never shell out to `pkill`/`crontab` blindly** — minimal images ship neither (crontab only behind `probeBootCaps`), so `pkill -f … 2>/dev/null` was a SILENT no-op leaving one supervisor per deploy. `killPatternPrologue` glob-scans `/proc/*/cmdline` and ⚠️ **skips its own PPID chain**: every deploy command line contains the pattern it kills (a sentinel string protects only callers that carry it).
- ⚠️ **Boot persistence is BEST-EFFORT and every hook must be PROBED, not assumed** — `probeBootCaps` asks the target which hooks it actually *executes*, then `installBootHook` installs all of them (init.d `S99plc-agent` + the **`initdefault` runlevel** symlink, `@reboot` cron, `rc.local`) and **read-back-verifies each**, else `none` + a warning; never fail a deploy over it. Two silent no-ops came from assuming: BusyBox/Yocto init never reads `/etc/rc.local` (it runs `rcS` → `rc<N>.d/S*`), and BusyBox `sed` rejects the GNU `0,/re/` first-match address — both reported success. Verified by reboot on rpi3bplus. SSE topic `server-deploy-progress`.
- Auth tries `ssh.Password` **AND** `ssh.KeyboardInteractive` (same password) — PAM-only servers offer only the latter.
- ⚠️ Host keys are TOFU (`AppDataDir/known_hosts`) but a **changed key is auto-retrusted** — deliberate, no MITM protection; discuss before changing.
- ⚠️ **Board → triple/flags is ONE function, `boardTargetFor`** (Build & Send, field hot-swap host + logic) — the hot-swap path had its own table and built aarch64 for `generic_linux_x64`/armv7. `compileForTarget` removes `runtime.bin.kind`, else a plain binary passed the hot-swap-host check.
- ⚠️ **`serverBinaryForBoard` maps board-id prefix → server arch** (aarch64 → `_arm64`, `bb_` → `_armv7`, else amd64); an unlisted aarch64 family ships the wrong arch.
- ⚠️ **Re-run `server/build.sh` after editing `server/`** — it is the only writer of `resources/<triple>/server/`, which the deploy reads.

## Packaging & toolchain

**`packaging/`** holds only three scripts + README, each emitting ONE self-contained gitignored artifact beside itself (AppImage, NSIS `.exe`, `.dmg`). **[`packaging/README.md`](../packaging/README.md) is the full reference.**
- ⚠️ **`build-mac.sh` must run on a Mac** (hdiutil/codesign/sips) and hard-fails elsewhere; Windows cross-builds on Linux via `makensis`.
- ⚠️ **The macOS artifact is not self-contained** — Apple's SDK can't ship, so local sim resolves it at run time (`paths.go MacOSSDKPath` ← `xcrun`) and needs `xcode-select --install`; Build & Send needs nothing extra.
- ⚠️ **Locate the bundled GCC dir by GLOB, not from the compile triple** (`paths.go LLVMGCCInstallDir`, used as `-B`/`-L`): sysroots name it with a vendor clang does not auto-detect (`arm-none-…`, `x86_64-buildroot-…`; aarch64 matches by luck), so armv7 **and x86_64** `-static` builds died with `cannot open crtbeginT.o` — all three Linux targets pass `-B`, and `setup_toolchain.py` harvests `lib/gcc` into each of their sysroots. Version dirs use `compareVersionStrings` (numeric).

- ⚠️ **Every link line wraps `resources/<triple>/lib/*.a` in `-Wl,--start-group`** (`staticArchiveLinkArgs`, all six link sites) — the archives depend on each other and a classic linker scans each one ONCE in order, while `CollectStaticArchives` sorts by BYTE value, putting `libTrajectoryGenerator.a` ahead of the `libkron_axis.a` that needs its `MotionLimitsInit`/`GenerateTrajectory`/`BrakeDistance`. It hid for as long as only `-fuse-ld=lld` paths linked these (LLD registers every member up front and ignores order) and surfaced the moment the axis engine moved into the loader-host, which links with the default linker. ⚠️ **Never on Mach-O** — ld64 rejects the flag and already re-scans. Adding an inter-dependent archive therefore needs no hand-kept order.

**Build output** under `~/.local/share/com.plceditor.app/build/` (`paths.go`): ⚠️ **split by consumer** — `sim/` (local sim: `sim_runtime.bin` `-O0 -g`, hot-swap slots, `retain.dat`) and `target/<board>/` (Build & Send: cross `-O3` `runtime.bin`, `last_board` picks the deploy source), each with its own `plc.c`/`variables.json`. A shared dir let a cold sim build and a cross build clobber each other; the binaries still **must not share a name** (`host-agent/CLAUDE.md`).
## Simulation, hot-swap & PlcState
**PlcState:** the transpiler always emits ONE struct holding all mutable state (globals, program locals, FB instances, shadow vars, edge memory, exec-time), reached via file-scope `static PlcState *S`; FB-locals stay `instance->…`. Non-zero initials go to `plc_state_init()`.
- ⚠️ **`__plc_state` must have EXTERNAL linkage in the non-hot-swap build** (`#ifdef PLC_HOTSWAP` keeps it static; the host owns state there) — as static under `-O3`, SROA dissolves it and the DWARF read finds nothing. The sim therefore builds `-O0 -g`; `compileForTarget` stays `-O3`.
- ⚠️ **Filename separation:** local sim = `sim_runtime.bin`, target/hot-swap = `runtime.bin`. Sharing a name let a Build & Send clobber the sim with a wrong-arch, no-DWARF binary.

### Hot-swap — the DEFAULT simulation runtime
A stable **loader-host** owns `PlcState` + the shm mirror + timing + scan threads; a swappable **`logic.so`** holds POU logic. `-DPLC_HOTSWAP` turns the same `plc.c` into the `.so` behind a fixed ABI (`plc_state_size`, `plc_bind`, `plc_task_body_<i>`, `plc_state_layout_hash`, …). On `SIGUSR1` the loader-host (`hotswaphost/host.c`) parks task threads on a scan-boundary barrier, `dlclose`+`dlopen`s, re-binds the SAME `PlcState`, and **rolls back** on failure.

- ⚠️ **`logic.so` is `dlopen`ed `RTLD_LOCAL`** — GLOBAL let generation N+1 bind to N's archive symbols (`TON_Call`…), pinning N through its `dlclose`, so dlopen of that slot path two swaps later returned the STALE handle: every second swap ran old code and reported OK. A still-mapped path is refused (`FAIL <gen> STALE`, `RTLD_NOLOAD` probe). ⚠️ **Never add `-Bsymbolic`** — archive calls (`KronAxis_*`, `kron_ec_*`) must keep resolving to the HOST's stateful copy.

**Generations — bounded 2-slot ping-pong** (`hotswaplib/`):
- ⚠️ Exactly two slots `logic_0.so` ↔ `logic_1.so`; each swap targets the slot **not** running (`PingPongGeneration(confirmedGen)`) so numbers never grow (`NextGeneration` = highest+1 is deprecated). `CleanupExcept` deletes the other only after a confirmed `OK`.
- ⚠️ **Slot writes must be atomic** (names are reused): `.tmp` + rename gives a fresh inode, so an `mmap`'d `.so` is never truncated in place.
- ⚠️ **`plc_state_layout_hash()`** (FNV-1a over the `stateFields` *shape*) is the hard safety net — host.c refuses+rolls back any swap whose hash differs from the first cold-start bind's (always the ORIGINAL, so drift can't accumulate). ⚠️ It does **NOT** cover the TASK COUNT (removing a task leaves every field intact), and the scan threads are created once in `main()`, so `resolve_and_bind` **separately refuses `n != g_ntask`** (`TASKCOUNT`, handled like `LAYOUT` in App.jsx): a shrinking swap left `g_body[i≥n]` pointing into the `dlclose`d module, a growing one silently never ran the new task. Intervals stay swappable.
- ⚠️ **A signalled swap with an unreadable/empty `swap_request` writes `FAIL -1 NOREQUEST`** — it has no generation to name, so `PollSwapResult` accepts that one token regardless of generation (`hotswaplib.DetailNoRequest`); a bare return burned the agent's whole poll timeout as "outcome unknown".
- **`layoutSignature(...)`** (App.jsx) is the fast UX pre-check over `{task, variables, udts, blocks, ioEc}`; `blocks` = `stateBlocksSignature` covers every FB-style ladder block (shadow fields exist per BLOCK, not per declared variable) plus edge contacts/coils. ⚠️ `variableTableSignature` must read POU locals from **`p.content?.variables`**, not the legacy `p.variables`.
- **On a refused layout change the sim offers a rebuild+restart** (`offerSimRestart`); the field path stays warn-only. ⚠️ **Carry real state ONLY** — bare locals/globals + FB struct members; **skip** `__exec_us`, composites and **pin shadows** — identified by the transpiler's `debugDefaults[k].isPinShadow`/`pinDir`, ⚠️ never by an `_in_`/`_out_` name regex (it caught user variables like `in_speed`; the remote auto force-write then pinned them on the real PLC). An `in_` shadow holds the source's pin literal, so carrying it reverts a pin edit.

**HAL-to-host:** HAL functions are `static inline` over file-scope `static` fd arrays, so hot-swap mode emits `#define F __hs_F` trampolines (`host_glue.c`) compiled into the host — HAL + fds survive swaps. ⚠️ An EMPTY `host_glue.c`/`kron_hal.h` from the transpiler DELETES the file — skipping the write linked the previous project's glue (and brought up its EtherCAT bus on the real NIC).
⚠️ **EtherCAT IS trampolined (Linux); motion is not.** `__ec_cfg`, `__gpi_hw/_buf/__gpi` and the three bus threads are emitted into **`host_glue.c`** under `PLC_HOTSWAP`, and host.c calls the **weak** `__hs_ec_start()` (⚠️ BEFORE `plc_init_hs()` — axis init assumes the bus is up) / `__hs_ec_stop()` (after the task joins). Left in `logic.so` the SOEM socket died on the first `dlclose` and `plc_init_hs` runs on COLD START ONLY, so the bus never came back while the FBs still read OP from a zeroed `__ec_cfg`. Hence the master init is split out of `PLC_Init` (`#ifndef PLC_HOTSWAP`) while axis init stays (it writes `S->`). ⚠️ Any bus edit needs a host rebuild, not a swap — `ioEcSignature` stringifies all of `busConfigs`, so it already refuses one.
⚠️ **The runtime runs PRIVILEGED (pkexec), so it is a ROOT child of an unprivileged agent — `kill(2)` is EPERM and every control path that assumed a signal had to be rebuilt.** Deliberate policy (raw socket + SCHED_FIFO); the password is asked per run, sim included. Consequences, all in `hotswaphost/host.c` + `hotswap.go`:
- ⚠️ **Swap and stop have FILE triggers** (`watch_files_thread`, 10 ms poll). `swap_request` is REWRITTEN per swap (⚠️ atomically, tmp + rename) and never deleted, so the trigger is a **change** (`ino`+size+mtime ns — `st_mtimespec` on macOS, `HS_MTIME_NSEC`) with the baseline taken at startup; the watcher fires only on a COMPLETE request (ends in `\n`, parses) and the baseline is advanced by the swap that READ the file (else signal + watcher swapped one request twice) — existence would re-swap forever, and a leftover request would swap on boot. `stop_request` is created by the agent and removed by the host, so existence IS the test. Signals stay installed (faster, and a KronServer-started runtime still gets them); ⚠️ **a failed swap signal is NON-fatal** — it used to 500 "signal failed" while the file trigger did the swap underneath.
- ⚠️ **host.c chowns what it creates to `PKEXEC_UID`/`SUDO_UID`** — the 0600 shm mirror (else the agent gets EACCES and every live value freezes at zero, sim looking alive) and `swap_result` (else the agent's pre-swap truncate fails and every swap reads the previous outcome). Never guessed from the filesystem.
- ⚠️ **`plc_host` takes `<logic.so> <buildDir>` and `chdir`s itself** — every control file is `./`-relative and pkexec's cwd handling is not worth betting the swap protocol on; argv[1] is made absolute BEFORE the chdir, or dlopen fails on a relative path with a message naming nothing.
- Stop order is `stop_request` → SIGTERM → Kill → `privilegedKill` (prompts again, so only after the graceful path timed out; grace = max(1.5 s, longest task + 0.5 s), ≤10 s). ⚠️ **Under sudo `cmd.Process` is SUDO** — killing it orphaned the root host; host.c writes `./plc_host.pid` and the kill targets that (checked against `/proc/<pid>/cmdline`). The scan sleep is ≤50 ms slices toward the same absolute deadline so stop latency is not the task interval; a privileged cold start waits 90 s (the password prompt is inside it). The legacy plain sim has NO file trigger — only `privilegedKill` stops it.

⚠️ **The spawned runtime's stdout/stderr are CAPTURED** (`runtimelog.go` → `<buildDir>/runtime.log` + its OWN `runtime-log` SSE topic, never `build-command` — these are not build commands). ⚠️ **Classified and folded before they reach the editor**: `runtimeLogLevel` routes trouble to Warnings/Errors and lets only a handful of progress lines into Messages, everything else stays in the file — a stuck bus narrates itself forever and buried every real message; identical consecutive lines fold into "repeated N more time(s)" within a 10 s window; the UI stream caps at 500 lines/run, the file never does. ⚠️ A line matching no rule is HIDDEN, so a new diagnostic needs a rule — `No EtherCAT slaves found` matched nothing and was invisible until a test caught it. An unset `Stdout` in `os/exec` means **/dev/null**, so every `[host] …` line and the EtherCAT master's precise reasons — `[kronec] No EtherCAT slaves found on %s`, `Could not reach OP state`, `PO2SO SDO failed: slave %d 0x%04X:%02X`, the PDO-size mismatch report — were discarded, and a bus that never came up was indistinguishable from a PLC bug. Diagnostics only: a PLC program still publishes through SHM, never printf (`src/services/CLAUDE.md`).

⚠️ **RT priority is PER TASK** (`TaskManager.rtPriority`, default **99**, 1–99, distinct from `programs[].priority` = execution order): transpiler → optional ABI `plc_task_priority(i)` → `g_prio[i]`, applied by each scan thread and re-applied only when it changes, so a swap can retune it. **Optional on purpose** — a logic.so without the symbol gets 99, the value the runtime used to hardcode. ⚠️ **Hot-swap scan threads never asked for RT at all** before this (only the legacy single-binary build and the EtherCAT IO_Bus thread did), so the default sim AND every deployed `runtime.bin` ran its PLC tasks at desktop priority even as root — and all three call sites ignored the return, so it was silent. They report now.

**Known gaps:** ⚠️ the local `plc_host` cache key is a **content hash over the loader source, the link recipe, `host_glue.c` AND — whenever that glue makes the host link them — `resources/<triple>/lib/*.a`** (`mixStaticArchives`). The archives were missing from it, and once the axis engine moved into the bus thread that hid a whole class of change: the host carries the motion stack, a swap recompiles only `logic.so` (whose `MC_*_Call`/`KronAxis_*` are undefined symbols bound to the HOST), so **a rebuilt `libkron_axis.a` took effect nowhere while every timestamp said the build was fresh**; a live swap on **physical hardware** is unverified.

### Windows & macOS simulation ⚠️
Both run the SAME hot-swap runtime; only the legacy plain sim is Linux-only. **Scan structure, ping-pong, swap protocol and force flags have exactly one implementation — keep it that way.**

| | Linux | Windows | macOS |
|---|---|---|---|
| mirror | `shm_open`+`mmap` in `/dev/shm` | `CreateFileMapping`, `Local\plc_runtime` | `mmap` on a real file `<buildDir>/plc_runtime.mirror` |
| module | `-shared` vs `-rdynamic` host | DLL + `plc_host.lib` import lib | `-bundle -bundle_loader plc_host` |
| swap signal | `SIGUSR1` | auto-reset Event `Local\kron_plc_swap` | `SIGUSR1` |
| sleep | `clock_nanosleep(ABSTIME)` | waitable timer | `mach_wait_until` |
| barrier | `hs_barrier_t` (mutex+condvar, stop-aware) — one implementation everywhere | | |

- ⚠️ **The agent's mirror is `mmap`ed (POSIX) / a mapped view (Windows), not file I/O** — the force mailbox needs atomics/CAS; one process-wide `mailboxWriter`, and an undersized mirror is refused (mapping it would SIGBUS).
- ⚠️ **Mirror offsets come from the CLIENT's variable table; every mirror read bounds-checks** — memory safety on Windows (`unsafe.Slice`), and on Linux/macOS it stops an out-of-range write silently EXTENDING the backing file.
- ⚠️ **The agent OPENS the mirror and event; the loader-host CREATES both** — a Win32 section/event lives only while a handle is open, and an auto-reset event silently latches an early swap signal.
- ⚠️ **Neither a PE DLL nor a Mach-O bundle resolves symbols from its loader** the way ELF does, so the host exports an import library (Windows) / is passed as `-bundle_loader` (macOS) — that keeps `__hs_*`, `us_tick`, `plc_stop`, `__plc_shm` in the host across a swap, and makes the loader-host a build-order prerequisite.
- ⚠️ **Windows locks a LOADED module's file** — the ping-pong handles it; **do not "simplify" to a single slot**. Slot files keep the `logic_<n>.so` name everywhere (a slot id, not a format claim).
- ⚠️ **Timing primitives lie by default:** winpthreads' `clock_nanosleep(ABSTIME)` doesn't block (a 10 ms task ran ~6 M times/s), macOS has none and `mach_timebase_info` isn't 1/1 on Apple Silicon; both derive a relative delta from one absolute deadline in **64-bit** (mingw's `tv_nsec` is 32-bit → an interval ≥ ~2.148 s went negative).
- ⚠️ **Host AND logic must link `-static` on Windows** (`windowsStaticRuntimeFlag` in both `compileHost` and `compileLogic`) — the linker prefers `libwinpthread.dll.a`, and the missing DLL surfaces only as "cold-start outcome unknown" / `LoadLibraryA` error 126.
- ⚠️ **Every cold-start failure path in host.c's `main` must `write_swap_result` before returning** — that file is the supervisor's only channel. Sample `exited(done)`/`ProcessState` **before** `Stop()` (kills then waits), else a real timeout reads as `exited (signal: killed)`.
- ⚠️ **The scan barrier is `hs_barrier_t` on EVERY platform** (Apple never implemented `pthread_barrier_*`, and the standard one can't be interrupted): phase-counted (a fast thread can't lap a straggler) and **stop-aware** — every exiting task thread calls `hs_barrier_abort`, else a sibling parked for a swap waited forever and the host never exited. Do NOT fork the scan loop.
- ⚠️ **macOS has no `/dev/shm`** (a `shm_open`'d object is invisible to the filesystem), so the mirror is a plain file — host.c's `mirror_path()` and `shmmirror_darwin.go`'s `mirrorPath()` must change together or every live value freezes at zero. `-lrt`/`-ldl` don't exist there, and the Mach-O link uses the **system linker, not lld**.
- ⚠️ **`__APPLE__` must stay in the transpiler's shm guard** — the hot-swap build needs the `extern __plc_shm` declaration and the `plc_shm_name`/`plc_shm_size` exports, or the sim runs fine with no live values and dead force-writes.
- ⚠️ Windows is verified under wine64 **and** on real Windows (two bugs appeared only on the latter); **macOS is unverified on real hardware**.

## Security (host-agent side)

Also: `build.go` restricts `Compiler` to a bare-name allowlist and rejects `..`/separators in `Output`; both agents set body limits + `ReadHeaderTimeout`.
- ⚠️ **`/api/host/build` REFUSES any `compilerArgs`** (400) — a prefix denylist over clang's spellings cannot be complete; its only caller (a Settings PoC button) sends none. `/api/host/delete-file` is scoped to `<AppDataDir>/esi` (it could delete the OAuth tokens/known_hosts), and the OAuth callback page escapes everything and sends a CSP (a reflected `error` param was XSS → the whole agent API).
- ⚠️ **`Output` containment needs `CompilerArgs` filtered too** (second line of defence) — clang honours the **LAST `-o`**, so the sibling field undid the check: `-o` now goes AFTER the caller's args AND `rejectedCompilerArg` refuses redirection (`-o`, `-Wl,-o`, `@file`) + code loading (`-fplugin=`, `-specs=`, `-B`, `-Xclang`, `-T`); bare operands stay legal so `-isysroot /path` works.
- ⚠️ **A pid is stale the moment its mutex drops:** `handleHotSwapSwap` signalled one read before a full clang run, so a concurrent Stop could free it for reuse — re-check and signal INSIDE one critical section (`writeProcMem` re-checks too). Deploy endpoints stay unauthenticated by design (trust model = same machine / trusted LAN); a shared secret on `/deploy/*` is the next step if that widens.

## EtherCAT on the host (local sim drives a real bus)

⚠️ **The LOCAL SIM DRIVES A REAL BUS on Linux** — `-DKRON_EC_SIM` (header stubs that fake OP) is gone from the hot-swap build, so SOEM opens the **PC's own NIC**. ⚠️ **An axis is faked by `KRON_EC_SIM`, never by the transpiler's `simMode`** — the generated `PLC_Init` sets `AXIS_REF.Simulation`/`servo[].present` from a `#ifdef KRON_EC_SIM` `__kron_bus_sim`, since a sim that really drives the bus must drive real axes: tied to `simMode`, the bus was real and every axis fake, and `KronAxis_WriteOutput`'s `slot==NULL || Simulation || !present` branch mirrors `PowerStatus = PowerEnabled` and writes NO CiA402 control word — MC_Power read Status=TRUE against a drive that never enabled (the slave's own Simulation checkbox still forces a fake axis). `compile.go` shares `ecSimFlag` for the same reason. Three things follow: the bus config carries a separate **`ifnameSim`** (the dev box is never `eth0`; empty → falls back to `ifname`); `ecSimFlag` (`hotswap.go`) re-adds the define whenever the host target lacks a `libsoem.a` that really exports `ecx_init` (⚠️ scanned in the archive bytes — `resources/` is gitignored, and Build Libraries emits a STUB-only archive that links fine and does nothing), and **always on Windows/macOS** (no npcap / contrib pcap bundled); a raw socket needs `CAP_NET_RAW`+`CAP_NET_ADMIN` and the scan threads need `CAP_SYS_NICE`, so **the runtime ALWAYS runs privileged, simulation included** (`runtimeLaunchCmd`, `netcaps_linux.go`) — ⚠️ **by an ADAPTIVE ladder, never one required package**: `pkexec` → `sudo -n` (NOPASSWD rule or live timestamp, the model KronServer already uses on target) → `sudo -A` with a GUI askpass (`ksshaskpass`/`ssh-askpass`, `SUDO_ASKPASS` in the child env) → direct. An HTTP agent has no tty, so plain `sudo` dies with "no tty present and no askpass program" — a prompter is always involved; and `pkexec` cannot be a requirement (Debian splits it out and does NOT install it — setuid-root, the PwnKit CVE lived there). See `host-agent/CLAUDE.md` for what that costs. Fallback when `pkexec` is missing: a direct spawn with `SysProcAttr.AmbientCaps`, live only if the AGENT binary itself was `setcap`'d — ⚠️ **asking for an ambient cap you do not hold fails `Start()` with EPERM**, so `netRawSysProcAttr` returns nil unless `/proc/self/status` `CapPrm` carries both. `/api/host/health` reports `etherCATCaps`+`platform`+`privilegedLauncher` — ⚠️ the editor offers the setcap grant ONLY when `privilegedLauncher` is false, since a root runtime makes the agent's own caps pointless; `POST /api/host/grant-ethercat-caps` `pkexec setcap`s **this agent's own** binary (never a caller-supplied path), refused while anything runs. ⚠️ **squashfs/AppImage cannot carry file caps at all.** ⚠️ **`lookupTool`, never `exec.LookPath`** for helpers: a desktop PATH excludes `/sbin`+`/usr/sbin`, so the agent claimed `setcap` was missing on a machine that had it, and `kill` is a shell builtin — pkexec/sudo need `/bin/kill`. Never fatal — `kron_ec_init` reports the bus absent instead of faking OP.
⚠️ **The bus watchdog BACKS OFF (100 ms → ×2 → 30 s cap) and says something actionable once.** `kron_ec_check_state` runs the library's recovery, and against a bus that CANNOT come up (as opposed to one that blipped) the old 10 Hz loop spammed "not OP / recovery failed" forever until the library's recovery re-entered its own `kron_ec_init` and died with a **double free**, killing the runtime. A real transient recovers on the first or second try, so backing off costs nothing. ⚠️ **Two library bugs live in `libkronethercatmaster.a` (private repo, prebuilt — not patchable here):** recovery calling `kron_ec_init` on a live SOEM context (the double free), and a DC bring-up that calls `ecx_configdc`+`ecx_dcsync0` back to back and then asks for OP once — **with no clock-convergence phase**, so every slave parks in SAFE-OP with `ALstatuscode=0x0000`. Proven on real hardware with `experiments`-style probes: DC on → SAFE-OP, DC off → OP, and the OP-request style (single round vs pumped) makes NO difference.
## Library builder (Settings → Libraries)
Four developer actions (need `git` + network; they rewrite repo files): **Build Libraries** (`libraries_kron.go`) → headers + one `lib<stem>.a` per source per target; **Build SOEM** / **Build CANopen** (`libraries_deps.go`); **Build Server** (`libraries_server.go`) → `resources/<triple>/server/`. `libraries.go` holds the matrix and shared helpers.

**Matrix (`libraryTargets`):** `x86_64/linux`, `x86_64/win32`, `arm/aarch64`, `arm/armv7`, plus `arm64|x86_64/macos` **only on a Mac** — ⚠️ macOS is host-only (Apple's SDK can't be redistributed).
⚠️ **A non-Krontek dependency of a library repo goes in `externalLibDeps`** (`libraries_kron.go`): this builder compiles top-level `.c` directly and never runs the repos' CMake, so a `FetchContent` dep is simply absent — KronMotion's `TrajectoryGenerator.h/.c` is cloned there, staged as a header and built as its own `libTrajectoryGenerator.a` (everything in `lib/` is linked).
⚠️ **`kronethercatmaster.h` is included into every generated `plc.c` and always does `#include "soem/soem.h"`**, so **every build needs `krontek-include/soem/soem.h`** — a fresh machine hits "soem.h not found" on its first compile until Build SOEM is run once.

**Rules deliberately changed from the Tauri original:**
- ⚠️ **Headers go to ONE place** — `installKrontekHeaders` must never become a per-target loop (a test asserts no per-target `include/`).
- ⚠️ **Build to staging, install only on success** — the original deleted every header and `.a` up front, so an aborted run left `resources/` stripped.
- ⚠️ **A local `KrontekLibraries/` is NOT written back to** — the original synced the clone onto it, overwriting the local edits `CLAUDE.md` makes it source-of-truth for.
- ⚠️ **`runWithTimeout` APPENDS to `cmd.Env`, never resets it** — `runUpdateServer` sets `GOOS`/`GOARCH`/`GOARM`/`CGO_ENABLED=0` first; resetting silently ships host-arch dynamic binaries to ARM boards.
