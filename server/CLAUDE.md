## Process & deploy endpoints
`server/`, cross-compiled by `server/build.sh` into `dist/` **and** `resources/<triple>/server/`. Go, static (`CGO_ENABLED=0`), ConnectRPC + protobuf, `mmap` on `/dev/shm`.
**RPC:** `Start` · `Stop` (SIGTERM 5 s → SIGKILL) · `WriteVar` · `ClearAllForces` · `StreamVars` (50 ms).
**HTTP:** `/deploy/runtime` (128 MB, atomic) · `/deploy/variable-table` · `/deploy/project-file` (⚠️ Build & Send POSTs it as a strict step, so an **older deployed KronServer without it breaks Build & Send**) · `/deploy/logic` · `GET /status` · `GET /stream/vars`.
- ⚠️ **Variable-table offsets are validated at load** (`Offset >= 0 && Size > 0 && Offset <= shmSize-Size`, same for `ForceFlagOffset`) — a corrupt table would otherwise panic via `WriteInitialValues` and crash-loop the agent forever.
- ⚠️ **`intentionalStop` is reset in `Start()`** and set by `Stop()` only when something runs, else a manual Stop suppresses the next crash event + AutoRun respawn.
- ⚠️ **`WriteInitialValues` runs via a `preStartHook`** — after the old process stops, before the new one spawns, so the dying runtime's shm sync can't clobber the initials. The same hook first runs `ClearForcesIfTableChanged`: flags are keyed by variable INDEX, so a redeployed table that inserted a variable left an old flag pinning a DIFFERENT one (a direct clear is legal only here — no runtime runs). A table is validated from the temp file BEFORE it replaces the deployed one.
- ⚠️ **Every write is a mailbox command that returns only after the runtime's ack** (`hotswaplib/shmcmd`): 409 = runtime stopped / protocol mismatch (old KronServer vs new runtime — redeploy both), 503 = mailbox full, 504 = no ack (the command is CAS-cancelled so a late runtime never applies it). Modes `force`/`pulse`/`unforce`. The old value-then-flag write lost writes while answering 200.
- ⚠️ **NaN/±Inf decode to JSON null** (`decodeValue`) — `encoding/json` refuses the whole map, so one REAL that divided by zero blanked every `/stream/vars` frame (the editor read the PLC as dead) and REST answered 200 with an empty body. 64-bit integers beyond ±2^53 travel as decimal strings (`jsonSafe64`).
- ⚠️ **`__forced` is a reserved key in `/stream/vars`** (sorted forced names; first event, on change, every 2 s; absent = unchanged; ignores the subscription) — split it off before merging into `liveVariables`. Forced = flag byte `0x81` (`shmcmd.IsForced`). REST: `GET /api/v1/forces`.
- ⚠️ **`/deploy/runtime` wipes `logic_*.so` + `swap_result`** (stale slots made a plain runtime start as a hot-swap host); a hot-swap deploy always follows with `/deploy/logic?cold=1`. `SwapLogic` accepts only a bare `logic_[01].so` (a path ran an arbitrary `.so` as root). A Stop bumps `restartEpoch`, which the crash-restart timer re-checks under `mu`.

- ⚠️ **`Server.Bind()` claims `:7070` BEFORE `pm.CleanupOrphanRuntime()`; `Start()` then serves.** A surplus agent must lose the port before touching shared state — two supervisors respawning one every 2 s each reaped the *live* runtime as an "orphan" (`crashed / exit code -1` after ~2 s, no stderr). Serving still begins after the reaper, so a `Start` RPC is never mistaken for one.
- ⚠️ **`/dev/shm` may not exist** (BusyBox/Yocto never create it): `ensureShmDir` mkdirs 1777 + best-effort tmpfs mount, else `O_CREAT` gives ENOENT, the agent `exit(1)`s in a 2 s crash-loop, and the runtime's `shm_open` fails the same way.

**HMI & auth:** 4-tier RBAC, SHA-256 salted passwords, 64-byte tokens (8 h), HttpOnly+SameSite=Lax, constant-time compares. ⚠️ Reflected values are HTML-escaped and JS-literal-encoded (was an XSS); `/hmi/api/write` is restricted to addressed variables, Operator+, and ⚠️ **refused (403) when no HMI user exists** (it used to be anonymous, bypassing the REST password) / 503 with no HMI deployed. The HMI page builds its DOM with `textContent` only (stored XSS from the unauthenticated `/deploy/hmi-layout`), the dedicated HMI listener is Origin-gated, login/write are JSON-only (415), and sessions/API tokens are revoked when users or the password change. A momentary button sends FORCE on press and UNFORCE on release, serialised per key. The UI is served under **`/hmi/`** and at the **root** of an operator port — ⚠️ handlers are base-aware via `hmiBase(r)`, and a new route without it breaks root serving.

**REST — [`server/API.md`](API.md) is the full reference; `ApiSamples/` the runnable one** (`kron_client.py` + numbered samples, stdlib only, variables discovered not hardcoded). ⚠️ Both docs still call the editor a **Tauri app** — stale (`CLAUDE.md`). Endpoints (`api.go`, Bearer from `POST /api/v1/auth`): `GET/POST /variables[/{name}]` · `GET /stream` (SSE, addressed only) · `POST /forces/clear` · `GET/POST /runtime[/start|/stop|/config]`.
- ⚠️ KronServer **auto-rehydrates `variable_table.json` on startup**, else the API password is empty after every reboot; the runtime need not run for REST to work.
- ⚠️ **`restart` is a transient action flag** — `handleDeployRuntime` only overwrites `runtime.bin` on disk while the running process keeps the old binary in memory, so Build & Send sends `restart: autoRun || isRunning` last. `/deploy/config` takes a partial body.
## Lossless capture ring
`GET /variables` returns only the latest value and `/stream/buffered` server-samples at ~1–1.5 kHz max on an SBC (Go ticker), aliasing a 100 µs task. The ring delivers EVERY kept scan of the **addressed** variables by flipping to **producer-push**: the scan loop itself appends. ⚠️ **The byte layout is the contract in [`server/RING_FORMAT.md`](RING_FORMAT.md)** — the C codegen and `server/ipc_ring.go` must match exactly.

**Producer (`generateMainLoop`):** per addressed SCALAR var, by owning task (**global → the FASTEST task**; unassigned → skipped). After `plc_shm_sync`: read `stride_N`, `if (scan_g++ % N) return;` else `__atomic_fetch_add(write_seq)`, memcpy into `s % nslots`, publish `slot.seq` with a RELEASE store LAST. Wait-free MPSC.
- ⚠️ **Gated `#if defined(__linux__) && !defined(PLC_HOTSWAP)`** (KronServer is the only consumer; a hot-swap `.so` doesn't own this memory) — Windows/macOS sim compiles via no-op stubs, and a "Go Live" project does NOT feed the ring.
- ⚠️ **Segment sizing is KronServer's, not the runtime's, and it MUST hang off `pm.preStartHook`** (`main.go` → `Server.SizeRingSegment`, `ringsize.go`). It `ftruncate`s `<shm>_ring` BEFORE the runtime spawns so the runtime *adopts* the size (it only sizes the segment itself when it finds one smaller than a record) and no env has to survive a `sudo` reset; it bumps `epoch` at init so a re-attached consumer resets its cursor. ⚠️ **`StartRuntime` is only ONE of four spawn paths** — the ConnectRPC `Start` (`service.go`, i.e. **the editor's Run button**), AutoRun at agent startup (`main.go`) and the crash-restart watchdog (`process.go`) all call `pm.Start()` directly. Sizing from `StartRuntime` alone therefore left the Run button producing the runtime's own **1 MiB** fallback — 0.43 s of slack at 100 kHz — while `/status` cheerfully reported the configured size, because it was computed and never applied. `preStartHook` is the single choke point all four share (it already carries `WriteInitialValues`).
- ⚠️ **Size = `min(P × 10 s, RingRAMPercent × MemAvailable)` — the percentage is a CEILING, not the target** (`ringBytesFor`; `P` from the deployed table via **`RecordStride`**, a record fills a whole slot). Bigger is worse for **latency**: the controller trips on `fill`, a *fraction*, so at 50 % of 3.4 GiB an overloaded consumer stays invisible ~6 min; 10 s absorbs a TCP hiccup and surfaces overload in ~5 s. `/status` reports `ring_produced_bytes_per_sec` for the real stall tolerance.
- ⚠️ **The controller's decrease must be MULTIPLICATIVE** (`api_ring.go`, `n -= n/10`) — an additive `n--` could not undo a doubling (a burst to `N=2048` took 3.4 min back; observed 0.08 % of scans delivered, `dropped=0`). ⚠️ **The analytic floor applies only while `fill > 0.1`**: with no backlog `D` measures *utilisation*, not capacity, so a floor from it held a high stride up by itself (a one-way trap).
- ⚠️ **The controller's `P` must be `WireBytesPerSec`, not `ProducedBytesPerSec`.** `D` is measured over whole frames, so `P` has to include the 16-byte per-record *wire* header (`u64 seq + u16 task_id + u16 payload_len + u32 scan`, `wireRecordHeaderBytes`; frame v2, `?v=2` required). Payload-only understated production 2.5× for one 8-byte variable, so `floor` came out that much too low. `ProducedBytesPerSec` keeps its payload-only meaning for the `/ring/info` field.

**Consumer (`ipc_ring.go` + `api_ring.go`):** ONE shared `RingConsumer` mmap serves all connections, each with its own `readSeq`, under `rc.mu`.
- ⚠️ **The header is RE-PARSED on epoch change** (`syncLocked`) — a Build & Send that changes the addressed set restarts the runtime with a different `record_stride`/`nslots`; without re-parsing the agent decodes new records with the old stride (only the first variable appears). The producer publishes `epoch` LAST, release store (ARM is weakly ordered).
- ⚠️ **A copied record is discarded (counted dropped) when `write_seq > s + nslots` after the copy** — the producer claims a seq before writing, so a slot can be overwritten mid-copy (torn record); it needs the producer's release fence after `fetch_add`. A slot unpublished for 100 ms while later ones exist is skipped, so a crashed/punched slot can't stall the stream. Only `loop()` clears `running` (a reconnect within 100 ms ran two controllers, each doubling N), and `ReclaimAll` runs under `c.mu`.
- ⚠️ **Never shrink the ring under a live mapping** (SIGBUS kills the agent): resize goes through `APIManager.resizeRing`, which remaps and invalidates the consumer until the next epoch.
- ⚠️ **`Drain` is byte-bounded per frame (4 MiB)** — else a client attaching to a live high-rate producer drains the whole ring in one allocation and **OOM-kills the agent** (4.3 GB RSS on a Jetson). On lap it counts `dropped`, resuming at the oldest surviving slot.
- ⚠️ **`stride_N = 0` means PAUSED — the producer stops writing entirely**, set at boot and when the last consumer leaves, so the runtime burns zero cycles. `SetStrideN` must NOT coerce `0→1` (codegen is `if (N == 0) return;`). Trade-off: no pre-connect history.
**Proven** on real hardware (Jetson Orin Nano, 10 µs task, 0 drops). ⚠️ **Deploying is TWO steps** — Build & Send ships only the runtime; the ring endpoints live in KronServer, so run `server/build.sh` + Deploy Server to Target (a stale agent 404s `/api/v1/ring/info`). **Gaps (v1):** scalars only; hot-swap doesn't feed the ring.
