# Lossless capture ring — byte-exact shared contract

The **capture ring** lets the REST API deliver *every* scan value of addressed
variables (not just the latest) even when a task runs far faster than the API can
poll. Two processes share it byte-for-byte:

- **Producer** = the PLC runtime (`runtime.bin`, generated by `CTranspilerService.js`).
  Each task thread appends its addressed variables into the ring on kept scans.
- **Consumer** = KronServer (`ipc_ring.go`), drains records and streams them over
  `GET /api/v1/stream/ring`, and writes the decimation stride back into the header.

⚠️ This file is the SINGLE source of truth for the layout. The C codegen in
`CTranspilerService.js` and the Go reader in `server/ipc_ring.go` MUST match it
exactly — change all three together (same rule as the `/dev/shm` mirror paths).

## Segment

- Name: `<shm-name>_ring` (default `plc_runtime_ring`) under `/dev/shm`.
- Created + sized by the **producer** (runtime) at init, size from env
  `KRON_RING_BYTES` (KronServer computes it from the RAM-% setting and passes it
  at launch; fallback `1<<20` = 1 MiB if unset).
- Consumer OPENS it read-write (reads records; writes only `stride_N`).
- All integers **little-endian** (every target arch is LE).

## Header (fixed `HEADER_BYTES = 256`)

| off | type | name | written by | meaning |
|----|------|------|-----------|---------|
| 0  | u32 | magic         | producer | `0x4B524E47` ("KRNG") |
| 4  | u32 | version       | producer | `1` |
| 8  | u32 | header_bytes  | producer | `256` |
| 12 | u32 | record_stride | producer | bytes per slot, `align8(16 + max_task_payload)` |
| 16 | u32 | nslots        | producer | `(total_bytes - 256) / record_stride` |
| 20 | u32 | total_bytes   | producer | whole segment size |
| 24 | u32 | ntasks        | producer | number of tasks that emit records (≤ 24) |
| 28 | u32 | flags         | producer | bit0 = ring enabled |
| 32 | u64 | write_seq     | producer (atomic fetch_add) | next record sequence; monotonic |
| 40 | u32 | stride_N      | **consumer** (atomic store) | global decimation stride, init `1` |
| 44 | u32 | reserved      | — | 0 |
| 48 | u64 | epoch         | producer | bumped at each runtime (re)start → consumer resets |
| 56 | u64 | reserved      | — | 0 |
| 64 | task_table[ntasks] | — | producer | one 8-byte entry per task (below) |

`task_table` entry (8 bytes each, starting at off 64, up to 24 entries):

| off | type | name | meaning |
|----|------|------|---------|
| +0 | u32 | period_us   | task scan period in µs |
| +4 | u16 | payload_len | bytes this task writes per record (Σ its addressed var sizes) |
| +6 | u16 | task_id     | task index (matches record.task_id) |

Records begin at offset `256`.

## Record (fixed `record_stride`, `nslots` of them)

| off | type | name | meaning |
|----|------|------|---------|
| 0  | u64 | seq         | the `write_seq` value under which this slot was written; `0xFFFFFFFFFFFFFFFF` = empty (init) |
| 8  | u16 | task_id     | which task wrote it |
| 10 | u16 | payload_len | valid bytes in payload |
| 12 | u32 | reserved    | 0 |
| 16 | u8[record_stride-16] | payload | addressed vars of `task_id`, in variable-table order (client decodes) |

## Producer algorithm (per task thread, C)

At init (once): map segment; if `magic` already set keep `epoch`, else zero header;
write magic/version/header_bytes/record_stride/nslots/total_bytes/ntasks/flags and
the task_table; set `write_seq = 0`; `epoch += 1`; init every slot's `seq` to
`0xFFFF...`; leave `stride_N` untouched if already set else `1`.

Per scan of task `g` (after `plc_shm_sync`, so values are final):
```c
uint32_t N = atomic_load(&hdr->stride_N, relaxed); if (N == 0) N = 1;
if ((scan_g++ % N) != 0) { /* skip */ }
else {
    uint64_t s   = atomic_fetch_add(&hdr->write_seq, 1, relaxed);
    Record *slot = base + 256 + (s % nslots) * record_stride;
    slot->task_id     = g;
    slot->payload_len = payload_len_g;
    memcpy(slot->payload, <task g addressed vars>, payload_len_g);
    atomic_store(&slot->seq, s, release);   // publish LAST
}
```
Multiple task threads are independent producers; `fetch_add` gives each a unique
`s`, so two writers never target the same slot unless a full lap (`nslots`) apart.
Wait-free: one relaxed add + one release store, never blocks on the consumer.

## Consumer algorithm (KronServer, Go)

Keep `readSeq` and `lastEpoch`. On epoch change → `readSeq = 0`, reset drop stats.
```
w = atomic_load(write_seq, acquire)
if w - readSeq > nslots:            // lapped: oldest records overwritten
    dropped += (w - readSeq) - nslots
    readSeq = w - nslots
for s := readSeq; s < w; s++ {
    slot = base + 256 + (s % nslots)*record_stride
    ss = atomic_load(slot.seq, acquire)
    if ss != s { break }            // producer mid-write (ss<s) → stop, retry next tick
    emit(slot.task_id, slot.payload[:payload_len])
    readSeq = s + 1
}
```

## Decimation control (KronServer, off the real-time path, ~100 ms tick)

- `P` (produced bytes/s) = Σ_g (payload_len_g / period_us_g) × 1e6, from `task_table`.
- `D` (delivered bytes/s) = EWMA of bytes actually written to the client socket.
- Backlog `fill = (write_seq - readSeq) / nslots`.
- Emergency: `fill > 0.5` → `N = min(2N, Nmax)` immediately (grow-fast; no swell).
- Analytic floor: `N ≥ ceil(P / (α·D))`, `α = 0.9` (stay strictly under the link).
- Relax: `fill < 0.1` sustained AND above floor → `N = max(1, N-1)` (shrink-slow).
- Store `N` into `stride_N` atomically. Single global N = proportional ("same
  ratio") decimation: every task keeps exactly `1/N` of its samples, uniformly
  strided on its own scan counter.

`Nmax` = a cap so a pathological link can't drive N to absurd values; the
`dropped` counter (from lapping) is the honest signal that even N=Nmax can't keep
up. Both are surfaced to the client per frame.
