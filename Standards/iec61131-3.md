# IEC 61131-3:2013 (3rd edition) — the language contract for KronEditor

This file is a **section-by-section digest of IEC 61131-3:2013** (the bilingual PDF in this folder), written so the transpiler (`src/services/CTranspilerService.js`, `src/services/stExpr.js`), the validator (`src/utils/stValidation.js`), the LD editor and the standard-block headers (`resources/krontek-include/kronstandard.h` & co.) can be checked against it. Every rule cites its clause (`§`), table (`T`) or figure (`F`) so it can be re-read in the PDF.

⚠️ = a rule the codegen silently breaks if ignored. **NORMATIVE** = "shall". *impl* = the standard leaves it to the Implementer (Kron must choose AND document the choice, §5.1 c/d).

> Read the root [`CLAUDE.md`](../CLAUDE.md) first (architecture, invariants). Transpiler internals: [`src/services/CLAUDE.md`](../src/services/CLAUDE.md). This file is deliberately long: it is the reference, not a summary — it is NOT auto-loaded (not a CLAUDE.md) — the root/services files point here, open it before a related change.

## 0. How to use this file (rules for Claude and contributors)

1. **The standard is the specification of the transpiler.** Any change to how ST/LD is parsed, typed, or emitted must be checked against the matching section below. If this file and the code disagree, the code is wrong **unless** the point is listed in §16 (deliberate Kron deviations) or is marked *impl*.
2. ⚠️ **Conflict protocol — if a developer request contradicts this file, WARN before implementing.** Name the clause (e.g. "§6.6.2.5.2 T22 fn. b: REAL_TO_INT rounds half-to-even, the request asks for truncation"), state the conforming alternative, and implement the non-conforming variant only after the developer explicitly confirms. A confirmed deviation is then recorded in §16 (rule + why), never left implicit.
3. **Still open the PDF for anything not quoted here.** The root `CLAUDE.md` rule "never cite a standard from memory" applies: quote the clause from this file or the PDF, or say you have not checked. To grep the PDF: `pdftotext -layout Standards/*IEC*61131*.pdf - | sed -n '1,13958p'` (lines after 13958 are the French half). Figures 11, 12 and 15 are garbled as text — render the page (`pdftoppm -f 69 -l 70 …`, `-f 118 -l 118`) and read the image.
4. **A missing standard feature must FAIL LOUDLY** (root `CLAUDE.md`), never be approximated: §5.1 b forbids requiring substitute constructs, and §5.1 f forbids **using a standard name (type, function, FB) for something whose behaviour differs from the standard**. A vendor block that behaves differently must get a non-standard name.
5. **The standard has internal inconsistencies** (§17). Where tables/figures and the Annex A grammar disagree, follow the reading given in §17 and do not "fix" the code toward the other one without discussion.

## 2. Compliance obligations (§5)

A tool claiming compliance (§5.1) **shall**:
- a) implement a *consistent subset* of the feature tables and publish an **Implementer's compliance statement** (F4: table no., feature no., language) (§5.3);
- b) not require substitute/additional language elements to achieve a feature;
- c) document **all implementer-specific extensions** (anything accepted that the standard prohibits or does not specify);
- d) document **all implementer-specific dependencies** — every *impl* item, plus limits (max lengths, counts, sizes, ranges);
- e) document **all errors** it detects and reports, at preparation (compile) time and at run time;
- f) **not use standard names** of types/functions/FBs for implementation features that behave differently.

Feature tables (§5.2): column 1 = feature number, used in the compliance statement. T29/T31/T33 use suffix `n` (supported by name, e.g. `ADD`) and `s` (by symbol, e.g. `+`).

## 3. Lexical elements (§6.1–6.3)

### 3.1 Character set, identifiers, keywords (§6.1, T1–T2)
- Characters per ISO/IEC 10646. ⚠️ **Case is NOT significant** in identifiers and keywords — except inside comments, string literals and STRING/WSTRING values (T1 fn. a). (Kron: `src/utils/iecNames.js`, root invariant.)
- **Identifier** = letter or `_` first, then letters/digits/`_` (§6.1.2). ⚠️ The underscore IS significant (`A_BCD` ≠ `AB_CD`). **Invalid:** multiple leading underscores (`__LIM_SW5`), embedded double underscores (`LIM__SW5`), a trailing underscore (`LIM_SW5_`). ≥ 6 characters of uniqueness required; max length *impl*.
- **Keywords** are case-insensitive, contain no spaces, and **shall not be used for any other purpose** (no variable named `END_IF`, `TON`… see note) (§6.1.3). Note: standard FB/function names (`TON`, `ADD`) are not keywords in the grammar, but §5.1 f and §6.6.3.2 rule 18 (an FB instance should not share a function's name) make reuse an error source — reject.
- **White space** (SP, TAB, NL…) allowed anywhere **except inside** keywords, literals, enumerated values, identifiers, direct variables, and delimiter pairs such as `(*` (§6.1.4). In ST, **end of line = a space** (§7.3.2): a statement may span lines and several statements may share a line.

### 3.2 Comments and pragmas (§6.1.5, T3, §6.2, T4)
- `// …` to end of line; inside it `(*`, `*)`, `/*`, `*/` mean nothing.
- `(* … *)` and `/* … */` multi-line; inside them `//` means nothing.
- **Nesting** is a feature (T3 3a/3b): `(* (* NESTED *) *)` and `/* /* NESTED */ */` — pairs of the SAME kind nest.
- Comments are allowed wherever a space is, **except inside string literals**, and are equivalent to a space (§6.1.5). (Kron: one scanner, `stripIecComments`.)
- **Pragma** `{ … }`: syntax/semantics *impl*; allowed where spaces are, not inside strings. An unrecognised pragma must not change semantics.

### 3.3 Numeric literals (§6.3.2, T5, Annex A)
- `_` between digits is ignored; **no other use** of `_` (`1__0`, `_1`, `1_` invalid).
- Integer: `-12`, `0`, `123_4`, `+986`. Leading zeros are decimal (`014` = 14 — ⚠️ C would read octal; Kron `iecNumberToC`).
- Real: **digits on both sides of the point are required** (`Signed_Int '.' Unsigned_Int ('E' Signed_Int)?`, Annex A): `0.0`, `0.4560`, `3.14159_26`, `-1.34E-12`, `1.0e+6`. `1.`, `.5`, and `1E5` are NOT real literals. A real is distinguished by the decimal point.
- Based: `2#1111_1111`, `8#377` (**octal deprecated**, T5 note 2 / Annex B), `16#FF` = `16#ff`. Base written in decimal. ⚠️ **Based numbers carry NO sign** and are bit-string literals.
- A positive integer literal may be used as a bit-string literal.
- BOOL: `0`, `1`, `FALSE`, `TRUE`.
- **Typed literal** `TYPE#value`: `INT#-123`, `INT#16#7FFF`, `WORD#16#AFF`, `WORD#1234`, `UINT#16#89AF`, `CHAR#16#41`, `BOOL#0`, `BOOL#TRUE`, `REAL#1.0`. Enumerated values use the same `Type#Value` form (§6.4.4.2).
- The maximum digits shall cover the full range/precision of every type the literal can represent (§6.3.2).
- ⚠️ Rules for **untyped** literals in expressions are *impl* (§6.6.1.6 rule 8): e.g. `myWord = NOT(0)` is ambiguous (16#FF? 16#FFFF?); the user can write `NOT(WORD#0)`. Kron must document its rule (stExpr's `#INT`/`#REAL` literal pseudo-types adopt the other operand's type).

### 3.4 Character string literals (§6.3.3, T6, T7)
- `'…'` = single-byte (STRING/CHAR); `$hh` = 8-bit code. `"…"` = double-byte (WSTRING/WCHAR); `$hhhh` = 16-bit code.
- `$` escapes (T7), letter case-insensitive: `$$` dollar, `$'` quote, `$L` line feed, `$N` newline, `$P` form feed, `$R` CR, `$T` tab, `$"` double quote. ⚠️ `$'` is valid only in `'…'`, `$"` only in `"…"`; a plain `"` is legal inside `'…'` and a plain `'` inside `"…"` (T6 1e/2d).
- Empty strings `''`, `""` are valid (T6 1a/2a).
- Typed: `STRING#'OK'`, `CHAR#'X'`, `WSTRING#"OK"`, `WCHAR#"X"`, `WSTRING#'OK'`, `WCHAR#'X'`.
- (Kron extension: a bare word on a STRING *pin* is text — `src/services/CLAUDE.md`. That is an editor convenience for LD pins, not ST syntax; in ST a string is always quoted.)

### 3.5 Duration literals (§6.3.4, T8, Annex A)
- Prefix `T#`, `TIME#`, `LT#`, `LTIME#` (any case). Units `d h m s ms us ns` (any case).
- Units in **descending order**, each optional, optionally separated by `_`: `T#25h_15m`, `t#5d_14h_12m_18s_3.5ms`, `t#12h4m34ms230us400ns`.
- ⚠️ **Only the last (least significant) unit may have a fraction**, written without exponent: `T#14.7s`, `T#14.7m`, `t#14.7d` OK; `T#1.5h30m` invalid.
- "Overflow" of the **most** significant unit is allowed: `T#25h_15m`, `T#90m`.
- Sign allowed after `#`: `T#-14ms`.

### 3.6 Date and time-of-day literals (§6.3.5, T9)
`DATE#1984-06-25`/`D#…`, `LDATE#`/`LD#`, `TIME_OF_DAY#15:36:55.36`/`TOD#…`, `LTOD#`/`LTIME_OF_DAY#`, `DATE_AND_TIME#1984-06-25-15:36:55.360227400`/`DT#…` (underscores allowed in the fraction: `.360_227_400`), `LDATE_AND_TIME#`/`LDT#`.

## 4. Data types (§6.4)

### 4.1 Elementary types (§6.4.2, T10)

| Type | Bits | Default initial | Range / note |
|---|---|---|---|
| BOOL | 1 | `FALSE` (0) | values 0 and 1 only |
| SINT / INT / DINT / LINT | 8/16/32/64 | 0 | −2^(N−1) … 2^(N−1)−1 |
| USINT / UINT / UDINT / ULINT | 8/16/32/64 | 0 | 0 … 2^N−1 |
| REAL | 32 | 0.0 | IEC 60559 single; results with denormals/Inf/NaN *impl* |
| LREAL | 64 | 0.0 | IEC 60559 double; same note |
| TIME | *impl* | `T#0s` | range & precision *impl* |
| LTIME | 64 | `LTIME#0s` | ⚠️ **signed 64-bit, unit NANOseconds** (fn. m) |
| DATE | *impl* | *impl* (start date *impl*) | |
| LDATE | 64 | `LDATE#1970-01-01` | signed 64-bit ns since 1970-01-01 |
| TIME_OF_DAY / TOD | *impl* | `TOD#00:00:00` | |
| LTIME_OF_DAY / LTOD | 64 | `LTOD#00:00:00` | signed 64-bit ns since midnight |
| DATE_AND_TIME / DT | *impl* | *impl* | |
| LDATE_AND_TIME / LDT | 64 | `LDT#1970-01-01-00:00:00` | signed 64-bit ns since epoch |
| STRING | 8 per char | `''` | variable length, max *impl* |
| WSTRING | 16 per char | `""` | variable length, max *impl* |
| CHAR | 8 | `'$00'` | |
| WCHAR | 16 | `"$0000"` | |
| BYTE / WORD / DWORD / LWORD | 8/16/32/64 | `16#00…` | bit strings, no numeric range |

Notes: the L-time types are stored in ns but their **update accuracy** is *impl* (fn. q). Character encoding of CHAR/STRING/WCHAR/WSTRING = ISO/IEC 10646 (fn. l).

⚠️ Kron: TIME and LTIME are both `int64_t` **microseconds** (root invariant) — fine for TIME (*impl*), a **deviation for LTIME** (§16).

### 4.2 STRING / WSTRING (§6.4.2.2)
- Max supported length *impl*; a declaration may give an explicit max: `STRING[10]` (must not exceed the impl max).
- ⚠️ **Single character access is 1-based**: `s[1]` is the first character and is a CHAR (WCHAR for WSTRING); writing `s[3] := c` replaces one character (example: `String1:='ABCD'`, `String1[3] := 'B'` → `'ABBD'`).
- `String2 := String1[2]` is legal only if implicit CHAR_TO_STRING exists (it does per F12); `String1[2] := String2` is an **error** (STRING_TO_CHAR is not implicit).
- Mixing single-byte and double-byte strings/chars is an **error**.
- `TYPE STR10 : STRING[10] := 'ABCDEF'; END_TYPE` → max 10, initial value `'ABCDEF'`, initial length 6.
- Assigning a longer string to a shorter target is *impl* (§6.6.1.2.2). Kron: `KRON_STRSET` truncates at 63 bytes without splitting a UTF-8 sequence — document as the impl choice.

### 4.3 Generic types (§6.4.3, F5) — only for standard functions/FBs
```
ANY
├─ ANY_DERIVED
└─ ANY_ELEMENTARY
   ├─ ANY_MAGNITUDE
   │  ├─ ANY_NUM
   │  │  ├─ ANY_REAL      REAL, LREAL
   │  │  └─ ANY_INT
   │  │     ├─ ANY_UNSIGNED  USINT, UINT, UDINT, ULINT
   │  │     └─ ANY_SIGNED    SINT, INT, DINT, LINT
   │  └─ ANY_DURATION   TIME, LTIME
   ├─ ANY_BIT           BOOL, BYTE, WORD, DWORD, LWORD
   ├─ ANY_CHARS
   │  ├─ ANY_STRING     STRING, WSTRING
   │  └─ ANY_CHAR       CHAR, WCHAR
   └─ ANY_DATE          DATE_AND_TIME, LDT, DATE, TIME_OF_DAY, LTOD
```
- A directly derived type has the generic of its base; a **subrange is ANY_INT**; every other derived type is ANY_DERIVED.
- ⚠️ Note **BOOL is ANY_BIT** (so AND/OR/XOR/NOT/SEL/comparisons accept it) but **not ANY_INT/ANY_NUM** (no arithmetic on BOOL).
- **Generic types in user-declared POUs are outside the standard** — a user FUNCTION with an `ANY_NUM` parameter is a vendor extension.

### 4.4 User-defined types (§6.4.4, T11)
`TYPE name : <declaration> [:= init]; … END_TYPE`. A user type can be used anywhere its base type can.

**Initialisation** (§6.4.4.1.2, F6): a user init overrides the default initial value; it is a **literal or a constant expression** (`12*24`) of a compatible (same or implicitly convertible) type. F6: ANY_UNSIGNED ← non-negative integer literal/const expr; ANY_SIGNED ← integer literal/const expr; ANY_REAL ← numeric literal/const expr; ANY_BIT ← unsigned integer literal/const expr; ANY_STRING ← string literal; ANY_DATE ← date literal; ANY_DURATION ← duration literal.

| Kind | Syntax | Default initial value | Rules |
|---|---|---|---|
| Enumeration (§6.4.4.2) | `Light : (Red, Amber, Green) := Amber;` | ⚠️ **the FIRST identifier** | value only from the list; ordered set; different enum types may reuse an identifier; qualified `Light#Red` (prefix forbidden *inside* the list); ⚠️ **an ambiguous unqualified literal is an ERROR** (`Red` declared in two enums); max count *impl* |
| Named values (§6.4.4.3) | `Light : INT (Red := 1, Amber := 2, Green := 3) := Green;` | the **first** element | does NOT restrict the range — any base value assignable, arithmetic allowed (`x := Amber + 1`); qualified `Light#Red`; ambiguity = error |
| Subrange (§6.4.4.4) | `ANALOG_DATA : INT(-4095..4095) := 0;` | ⚠️ **the LOWER limit** (−4095), not 0 | limits literals or constant exprs; value outside the range is an **error** (§6.6.1.2.2); generic = ANY_INT |
| Array (§6.4.4.5) | `ARRAY [1..16] OF X := [8(-4095), 8(4095)]` | each element's type default | see 4.5 |
| Structure (§6.4.4.6) | `STRUCT a : INT := 1; b : X; END_STRUCT` | members' type defaults | see 4.6 |
| Relative layout (§6.4.4.7) | `head AT %B0 : INT; flag AT %X3.0 : BOOL;` / `STRUCT OVERLAP` | | no overlap unless `OVERLAP`; bit offset 0..7, bit 0 = rightmost; no whitespace in the location; **overlapped structs cannot be initialised explicitly** |
| Partly located members (§6.4.4.8) | `IN AT %I* : BOOL;` | | must be fully located in VAR_CONFIG for every instance (else error); not allowed in VAR_INPUT / VAR_IN_OUT / VAR_TEMP |
| Directly derived (§6.4.4.9) | `CNT : UINT; FREQ : REAL := 50.0; Cfg2 : Cfg := (MIN_SCALE := 0);` | the base type's | used to define type-specific initial values; unlisted struct members keep the original defaults |
| FB types as elements | `TONs : ARRAY[1..50] OF TON := [50(PT := T#100ms)];` `Cooling : TOF := (PT := T#100ms);` | | FB types and classes are allowed as array and struct elements (T11 5, 7) |
| Constant expression init | `PIx2 : REAL := 2 * 3.1416;` | | T11 12 |

### 4.5 Arrays (§6.4.4.5)
- Element types: elementary, user-defined, **FB types**, classes. Multi-dimensional: `ARRAY [1..2, 1..3] OF INT`, accessed `TBT[i, j]`.
- ⚠️ **It is an ERROR if a subscript is outside the declared range** — at run time for a computed index (NOTE). (Kron: `KRON_IDX` stops the PLC — conforming detection, root/services.)
- Max dimensions, size and subscript range *impl*. Limits are literals or constant expressions.
- **ST**: a subscript is any ANY_INT expression. **LD/FBD/IL**: a subscript is restricted to a single-element variable or an integer literal (§6.4.4.5.1).
- **Initialisation** (§6.4.4.5.2): list with repetition `n(v, …)`; ⚠️ **the rightmost subscript varies fastest** (row-major): `TBT : ARRAY[1..2,1..3] OF INT := [9, 8, 3(10), 6]` → `TBT[1,1]=9, [1,2]=8, [1,3]=10, [2,1]=10, [2,2]=10, [2,3]=6`; `[2(1,2,3)]` = 1,2,3,1,2,3; `n()` = n default values (Annex A).
- ⚠️ **Too many initial values → the excess (rightmost) ones are ignored; too few → the rest get the type default; in EITHER case the user SHALL be warned at compile time.**
- Variable-length arrays: §5.4.

### 4.6 Structures (§6.4.4.6)
- Element access with single periods: `CONF.CHANNEL[2].MIN_SCALE`, `MODULE_8_CONF[5].RANGE`.
- Max elements, max size and max nesting *impl*.
- ⚠️ **Two structured variables are assignment-compatible only if they are of the SAME data type** (not "same shape").
- Initialisation priority (lowest → highest): member type default → member init inside the STRUCT → **initialisation list at the declaration** `(RANGE := BIPOLAR_10V, MIN_SCALE := -1023)`; arrays of structs: `[8((RANGE := BIPOLAR_10V))]`.

### 4.7 References (§6.4.4.10, T12) — not supported by Kron
`REF_TO <defined type>`; default `NULL`; init `REF(var)`; `REF()` of a VAR_TEMP or of a function's local is **not permitted**; assignment ref ← ref only if the same type or a base type; refs **shall not be used as in-out variables**; dereference **explicitly** with `^` (`r^.SC1`, `r^[12]`); **dereferencing NULL is an error**; compare `= NULL`; reference arithmetic is out of scope.

## 5. Variables (§6.5)

### 5.1 Declaration and initial values (§6.5.1, T13, T14)
- `a, b : INT;` — a list of names, a colon, a type (elementary, previously defined, reference, or an **instant** type such as `ARRAY [1..8] OF REAL`), an optional `:= init`.
- **Initial value precedence** (lowest → highest): T10 default (NULL for references) → the type's `:=` init (TYPE) → the variable's `:=` init (VAR) → instance-specific `VAR_CONFIG` (§6.8.1; "always overrides type-specific").
- Init values are literals or **constant expressions**; constants may refer to earlier constants: `VAR CONSTANT PI : REAL := 3.141592; PI2 : REAL := 2.0*PI; END_VAR`.
- ⚠️ **No initial values in VAR_EXTERNAL** (§6.5.1.3).
- `OKAY : STRING[10] := 'OK'` → length 2.

### 5.2 Variable sections (§6.5.2, F7)

| Section | Meaning |
|---|---|
| `VAR` | internal; **persists between calls of PROGRAM / FB**; in a FUNCTION (and METHOD) it does **not** persist (= VAR_TEMP) |
| `VAR_TEMP` | temporary in FB/PROGRAM/METHOD: **allocated and initialised to the default EVERY call**, never persists |
| `VAR_INPUT` | supplied from outside; ⚠️ **not modifiable inside the POU** |
| `VAR_OUTPUT` | supplied to the outside |
| `VAR_IN_OUT` | supplied from outside, modifiable inside, returned |
| `VAR_EXTERNAL` | refers to a `VAR_GLOBAL` (type must agree) |
| `VAR_GLOBAL` | global declaration (configuration, resource, or PROGRAM, T47 8a) |
| `VAR_ACCESS` | access path (§6.8) |
| `VAR_CONFIG` | instance-specific location / initial value (§6.8) |

Qualifiers: `RETAIN`, `NON_RETAIN`, `CONSTANT`, `PUBLIC`, `PRIVATE`, `PROTECTED` (default for classes), `INTERNAL`. ⚠️ **FB instances shall not be declared in a CONSTANT section** (F7 fn. a).

**Scope** (§6.5.2.2): declarations are local to their POU; other POUs reach them only through inputs/outputs; globals only through `VAR_EXTERNAL`.

⚠️ **Errors (§6.5.2.2):** a POU modifies a `CONSTANT` variable or a `VAR_INPUT`; a `VAR_GLOBAL CONSTANT` is used in a `VAR_EXTERNAL` *without* CONSTANT. F8:

| containing | using | allowed |
|---|---|---|
| `VAR_GLOBAL X` | `VAR_EXTERNAL CONSTANT X` | yes |
| `VAR_GLOBAL X` | `VAR_EXTERNAL X` | yes |
| `VAR_GLOBAL CONSTANT X` | `VAR_EXTERNAL CONSTANT X` | yes |
| `VAR_GLOBAL CONSTANT X` | `VAR_EXTERNAL X` | **NO — error** |

(Kron has no VAR_EXTERNAL: globals are implicitly visible. The CONSTANT rule still applies: **writing a CONSTANT global anywhere must be a compile error**.)

Max variables per section *impl*.

### 5.3 Variable-length arrays (§6.5.3, T15)
- `ARRAY [*, *] OF INT` — **only** as VAR_INPUT/VAR_OUTPUT/VAR_IN_OUT of FUNCTIONs and METHODs and as **VAR_IN_OUT of FBs**. The number of dimensions of actual and formal parameters must match.
- Standard functions `LOWER_BOUND(ARR, DIM)` / `UPPER_BOUND(ARR, DIM)` (DIM 1-based; DIM 0 or > dims = error). Example: `A2 : ARRAY [1..20, -2..2]` → `LOWER_BOUND(A2,2) = -2`. A row may be passed: `SUM(A2[2])`. The parameter shall be connected to a static variable (§6.6.2.3).

### 5.4 Constants (§6.5.4)
`VAR CONSTANT … END_VAR`; the rules of expressions apply; a constant is a valid operand of a **constant expression** (§6.6.1.2.4: literals, constant variables, enum values, operators).

### 5.5 Directly represented variables (§6.5.5, T16)
- `%` + location `I` (input) / `Q` (output) / `M` (memory) + size `X` or none (BOOL) / `B` BYTE / `W` WORD / `D` DWORD / `L` LWORD + one or more unsigned integers separated by `.` (hierarchical, leftmost = highest level; levels *impl*). `%IX1` ≡ `%I1`.
- The Implementer **shall specify** the mapping to physical/logical locations.
- `name AT %IW6 : INT;` gives a symbol and type; a UDT/array may be located (`OUTARY AT %QW6 : ARRAY[0..9] OF INT`); sizes need not match, overlap permitted.
- Partly specified `%I*`/`%Q*`/`%M*`: only in internal variables of programs/FBs, never VAR_INPUT/VAR_IN_OUT; fully located in VAR_CONFIG for every instance or it is an **error**.
- ⚠️ **Direct variables in POU bodies are deprecated** (§6.5.5.1, Annex B).
- Initialisation of system inputs is *impl*.
- Kron's IEC address column (`%MX…`) is a REST label consistent with T16 sizes (`src/utils/iecAddress.js`); keep the prefix ↔ type rule identical to T16.

### 5.6 RETAIN / NON_RETAIN (§6.5.6, F9)
- **Warm restart:** `RETAIN` → the value at stop; `NON_RETAIN` → initialised; **neither given → *impl*** (Kron: initialised — document it).
- **Cold restart:** everything initialised.
- Initialisation order: variable's own init → type's init → T10 default. Inputs of the PLC are initialised *impl*.
- Allowed on static `VAR`, `VAR_INPUT`, `VAR_OUTPUT`, `VAR_GLOBAL`; ⚠️ **not on `VAR_IN_OUT`** (and by nature not on VAR_TEMP/function variables).
- On an **FB/class/program instance** (`VAR RETAIN TMR1 : TON;`): every variable of the instance gets the qualifier, **except** variables explicitly qualified in the type, and nested FB/class instances, which follow their own type declarations. On a **struct instance**: every element, recursively.
- (Kron: offered for globals and program locals incl. FB instances; not inside FBs/functions — `src/services/CLAUDE.md` § Retentive.)

## 6. Common POU rules (§6.6.1)

### 6.1 General (§6.6.1.1)
POUs = FUNCTION, FUNCTION_BLOCK, CLASS, PROGRAM (+ methods). ⚠️ **Recursion is *impl*** — Kron must decide and document (recursion in a scan-cycle PLC is normally forbidden; C would silently allow it for functions). Max POUs/instances *impl*.

### 6.2 Assignment (§6.6.1.2.2)
- Same type: always. STRING ↔ STRING, WSTRING ↔ WSTRING (longer source → *impl*).
- A subrange variable can be used wherever its base can; ⚠️ **a value outside the subrange is an error**.
- A derived type can be used wherever its base can. Array assignment rules beyond "same type" are *impl*.
- Operators: `:=` (right → left), and `=>` (left → right) **only in call parameter lists, only to fetch a VAR_OUTPUT**. `A_struct1 := B_Struct1` is legal (same type).
- Graphically, a connection line is an assignment; `MOVE` is the graphical assignment.
- Expression (§6.6.1.2.3): operands + operators, evaluated by the language's precedence. Constant expression (§6.6.1.2.4): literals, constants, enum values, operators — evaluated at compile time.

### 6.3 Partial access to ANY_BIT (§6.6.1.3, T17)
- `v.%Xn` or `v.n` (bit, `%X` optional), `v.%Bn`, `v.%Wn`, `v.%Dn`; index = integer literal, **0 = least significant**.
- Valid: BYTE bits 0..7; WORD bits 0..15, bytes 0..1; DWORD bits 0..31, bytes 0..3, words 0..1; LWORD bits 0..63, bytes 0..7, words 0..3, dwords 0..1. Out-of-range index = error.
- The standard defines it for **ANY_BIT** (BYTE…LWORD); on ANY_INT it is a vendor extension.
- ⚠️ **Not on a direct variable** (`%IB10.%X1` forbidden).
- The Annex A grammar puts partial access in `Variable_Access` (expressions = read). Writing `w.3 := TRUE` is not in the grammar — if supported, it is an extension (document it).

### 6.4 Calls (§6.6.1.4, F10, T20)
1. ⚠️ Unnamed inputs of standard functions are named **`IN1, IN2, …`** top to bottom; a single unnamed input is **`IN`**. (MUX is the exception: `IN0…INn-1`, T32 fn. b.)
2. ⚠️ **ERROR if a VAR_IN_OUT is not "properly mapped"**: it must be connected (graphically, on the left) or assigned with `:=` to a **non-CONSTANT variable** declared in the caller's VAR_IN_OUT, VAR, VAR_TEMP, VAR_OUTPUT or VAR_EXTERNAL, or to a properly mapped in-out of another call. **A literal or an expression on an in-out is an error** (example: `X1*X2` wired to `ACCUM.A` is "NOT ALLOWED", §6.6.3.2 ex. 2e).
3. A properly mapped in-out may be read back on the right side / assigned to a VAR, VAR_OUTPUT, VAR_EXTERNAL. An ambiguous resulting value is an error.
4. An FB instance name may be an input if declared `VAR_INPUT` (its variables are read-only inside) or `VAR_IN_OUT` (read/write, and it may be called).

**Textual call** (§6.6.1.4.2): name + parenthesised, comma-separated list.
- **Formal**: `IN := v` for inputs and in-outs, `OUT => var` for outputs; **complete or incomplete**; ⚠️ **an input not listed takes the declared initial value of the called entity (or the type default)** — for functions; FB inputs keep their stored value (§7.1); **order is NOT significant**; EN/ENO usable. `A := LIMIT(EN := COND, IN := B, MN := 0, MX := 5, ENO => TEMPL);` `A := LIMIT(IN := B, MX := 5);`
- **Non-formal**: ⚠️ **exactly the same number, order and types** of parameters as the declaration, excluding EN/ENO. `A := LIMIT(B, 0, 5);`. A function without result with outputs: `myFun(150, var);` — outputs are positional too.
- Negated output in a formal call: `NOT ENO => NO_ERR` (F10 c).
- `=>` target must be a variable: `My_Function(In1 := a, Out1+Out2 => d)` is **not permitted** (§6.6.2.3 ex. d).

**Graphical call** (§6.6.1.4.3): rectangular block; inputs left, outputs right; name inside; EN/ENO at the top-left/top-right; the function **result** at the top-right (below ENO), with no name shown; negation = small circle **outside** the block (performed outside the POU); ⚠️ **negation is forbidden on in-out variables** (T20 note 6, T42 4); outputs may be left unconnected.

### 6.5 EN / ENO (§6.6.1.5, T18)
Declared as `VAR_INPUT EN : BOOL := 1; END_VAR` and `VAR_OUTPUT ENO : BOOL; END_VAR`.
1. **EN = FALSE → the POU shall not be executed and ENO is reset to FALSE.** The Implementer documents the details.
2. EN = TRUE → ENO := TRUE, then the body runs; the body may set ENO.
3. **An error during execution resets ENO to FALSE** (or the Implementer documents another disposition).
4. ENO = FALSE → the values of ALL outputs (VAR_OUTPUT, VAR_IN_OUT, result) are *impl*.
5. EN is set only as an actual parameter of a call. 6. ENO is transferred only as part of a call. 7. ENO is set only inside its own POU. 8. `REF(EN)`/`REF(ENO)` is an error.
- **Internal implementation** (EN tested inside; inputs and in-outs are still evaluated and stored in the instance) vs **external** (`IF cond THEN inst(...) ELSE X := 0;` — inputs not evaluated, not stored). ⚠️ **Kron must document which one it uses**, also for FB EN=0 (§6.6.3.4 rule 4: whether inputs/in-outs are set in the instance).
- T18 fn. a: the Implementer states in which languages EN/ENO are supported.
- In LD every block needs at least one BOOL input and one BOOL output for power flow (§8.2.6) — usually EN/ENO.

### 6.6 Type conversion (§6.6.1.6, F11, F12)
Applies to `:=`, `=>`, parameter passing, and operands within expressions.

**Implicit conversion rules:**
1. ⚠️ **shall keep the value and the accuracy** (never narrowing, never sign-changing);
2. may apply to typed functions; 3. to the assignment of an expression to a variable — ⚠️ *after* the expression has been evaluated in its own type (`myUDInt := myUInt1 * myUInt2` multiplies in **UINT**, then widens);
4. to input parameters; 5. to output parameters;
6. ⚠️ **shall NOT apply to in-out parameters** (an in-out actual must have exactly the formal's type);
7. may unify the operands of an operation/overloaded function (`myUDInt := myUInt1 * myUDInt2` → UDINT multiply);
8. the rules for **untyped literals** are *impl*.

**F12 — the complete set of implicit conversion paths** (plus their transitive closure):
```
BOOL → BYTE → WORD → DWORD → LWORD
SINT → INT → DINT → LINT              INT → REAL      DINT → LREAL      REAL → LREAL
USINT → UINT → UDINT → ULINT          USINT → INT     UINT → DINT       UDINT → LINT
                                      UINT → REAL     UDINT → LREAL
TIME → LTIME     DT → LDT     DATE → LDATE     TOD → LTOD
CHAR → STRING    WCHAR → WSTRING
```
**F11 "i" cells (implicit allowed), source → targets:**

| Source | Implicit targets |
|---|---|
| REAL | LREAL |
| DINT | LREAL, LINT |
| INT | LREAL, REAL, LINT, DINT |
| SINT | LREAL, REAL, LINT, DINT, INT |
| UDINT | LREAL, LINT, ULINT |
| UINT | LREAL, REAL, LINT, DINT, ULINT, UDINT |
| USINT | LREAL, REAL, LINT, DINT, INT, ULINT, UDINT, UINT |
| DWORD | LWORD |
| WORD | LWORD, DWORD |
| BYTE | LWORD, DWORD, WORD |
| BOOL | LWORD, DWORD, WORD, BYTE |
| TIME / DT / DATE / TOD | LTIME / LDT / LDATE / LTOD |
| CHAR / WCHAR | STRING / WSTRING |
| LREAL, LINT, ULINT, LWORD, LTIME, LDT, LDATE, LTOD, STRING, WSTRING | none |

**Consequences that matter for the typer (`stExpr.js`):**
- ⚠️ **Integer ↔ bit string is NEVER implicit**: `myWord := myInt` and `myInt := myWord` need `INT_TO_WORD`/`WORD_TO_INT` ("e").
- ⚠️ **Signed → unsigned is never implicit** (`INT → UINT` is "e"); **unsigned → the next wider signed is implicit** (`UINT → DINT`).
- ⚠️ **DINT → REAL, LINT → (L)REAL, UDINT → REAL, ULINT → anything are explicit only** (precision loss); `DINT → LREAL` is implicit.
- ⚠️ **No implicit narrowing**: `INT := DINT`, `REAL := LREAL` require explicit conversion.
- **"−" cells (no conversion defined at all, not even explicit)**: anything numeric/bit → **BOOL** except the bit-string `*_TO_BOOL` of T24 (see §17); BOOL/BYTE/WORD → REAL/LREAL; DWORD → LREAL; LWORD → REAL; REAL → LWORD and LREAL → DWORD/WORD/BYTE; every number ↔ duration/date type; every number ↔ string type. The Implementer may add its own conversions (documented).
- **"e" cells (explicit standard conversion function)**: every other numeric/bit combination; LTIME → TIME; LDT → DT, LDATE, DATE, LTOD, TOD; DT → LDATE, DATE, LTOD, TOD; LDATE → DATE; LTOD → TOD; WSTRING ↔ STRING; STRING → CHAR; WCHAR → LWORD, DWORD, WORD, CHAR; CHAR → USINT, LWORD, DWORD, WORD, BYTE, WCHAR; WORD → WCHAR; BYTE → CHAR; LREAL ↔ LWORD; REAL ↔ DWORD.
- STRING → WSTRING and CHAR → WCHAR are deliberately **not** implicit (character set).

Worked example (§6.6.1.6 ex. 6): `PartsRatePerHr := PartsDone / HoursElapsed;` (INT / REAL → implicit INT→REAL) and `PartsPerShift := TO_INT(ShiftLength * PartsRatePerHr);` (explicit back to INT).

### 6.7 Overloading (§6.6.1.7)
- Overloaded elements: standard functions (`ADD`, `MUL`, …), standard conversion functions (`TO_REAL`, `TO_INT`), standard FBs/methods (*impl*), and operators (`+`, `*`).
- ⚠️ If a system supports an overloaded element, **it shall apply to ALL suitable types of that generic type that the system supports** (e.g. if LINT exists, `ADD` must work on LINT).
- Inputs and outputs "of the same kind" (e.g. the operands and the result of `+`) **shall have the same type**; if they differ, the conversion is *impl* (subject to F11).
- Implicit conversion **follows the order of evaluation** of the expression.
- ⚠️ **The type of the variable receiving the result does NOT influence the type of the operation**:
  ```
  int3  := int1 + int2;   (* INT addition *)
  dint1 := int1 + int2;   (* INT addition, THEN converted to DINT — overflow happens in INT *)
  dint1 := dint2 + int3;  (* int3 → DINT, DINT addition *)
  ```
  ⚠️ C's integer promotion computes `int16 + int16` in `int` — see §16.

## 7. Functions (§6.6.2)

### 7.1 Semantics (§6.6.2.1–3, T19, T20)
- A function **stores no state**: no input, internal, or output value survives a call. ⚠️ Same inputs + in-outs + externals ⇒ same outputs, in-outs, externals and result. (System functions such as a clock or random number are the documented exception.)
- A function may return a result (element, array or struct), have outputs, and modify in-outs and VAR_EXTERNALs.
- ⚠️ **A function WITH a result may be used in an expression or as a statement (result discarded, T72 fn. b); a function WITHOUT a result shall NOT be used inside an expression.**
- Declaration: `FUNCTION name : TYPE` (omit `: TYPE` when there is no result) … `END_FUNCTION`. Sections: VAR_INPUT, VAR_OUTPUT, VAR_IN_OUT, VAR_EXTERNAL (modifiable), VAR_EXTERNAL CONSTANT (not modifiable), VAR / VAR_TEMP (both temporary, re-initialised every call: "VARs are static in function blocks" but NOT in functions — T19 2e). Inputs, outputs and temporaries may be initialised: `VAR_INPUT MN : INT := 0;`, `VAR_OUTPUT RES : INT := 1;`, `VAR I : INT := 1;`.
- ⚠️ **Unconnected input → its declared initial value** (the example gives `C : REAL := 1.0` "to avoid a division by zero error if the input is not specified").
- The result is assigned to the **function name** (`SIMPLE_FUN := A*B/C;`); see §10.4 for the "must assign" rule.
- Inputs, outputs and result are not stored, so they are assigned/read **immediately with the call**.

### 7.2 Typed vs overloaded (§6.6.2.4, T21)
- A typed variant appends `_TYPE`: `ADD_INT`, `ADD_REAL`, `MUL_REAL`, `DIV_REAL`, `SIN_REAL`, `MUX_INT`. The inputs and output have that type; implicit conversion may apply to the operands (`ADD_REAL(int_a, real_b)` is legal).
- Overloaded conversions `TO_xxx` / `TRUNC_xxx` may be typed by prefixing the source type: `INT_TO_REAL`, `REAL_TRUNC_INT`.
- `C := TO_REAL(A + B)` with INT A, B performs an **INT** addition first.
- If typed functions are supported, the compliance statement lists which functions are overloaded and which are typed (T21 fn. a). Overloading of **user** functions/FBs is out of scope.

### 7.3 Extensible standard functions (§6.6.2.5.1)
- An extensible function takes **two or more** inputs (max *impl*). In a **formal** call, the number of effective inputs is the **highest-numbered formal name used**: `ADD(Y1, Y2, Y3)` ≡ `ADD(IN1 := Y1, IN2 := Y2, IN3 := Y3)`.
- ⚠️ Missing intermediate inputs take their default: `MUX_INT(K := 3, IN0 := 1, IN2 := 2, IN4 := 3)` **= 0** (IN3 was not given → 0).
- Extensible: ADD, MUL, AND, OR, XOR, MAX, MIN, MUX, CONCAT, and the comparisons GT/GE/EQ/LE/LT (not NE).

### 7.4 Conversion functions (§6.6.2.5.2–7, T22–T27)

**Forms (T22):** `INT_TO_REAL(B)` (typed, input `IN`, output `OUT`) · `TO_REAL(B)` (overloaded) · `TRUNC(x)` (**deprecated**) · `REAL_TRUNC_INT(B)` · `TRUNC_INT(B)` · `WORD_BCD_TO_INT(B)` · `BCD_TO_INT(B)` · `INT_TO_BCD_WORD(B)` · `TO_BCD_WORD(B)`. The compliance statement lists the supported conversions and their effects (fn. a); the accuracy effects and run-time errors of conversions are *impl*.

⚠️ **Float → integer ROUNDS to nearest, ties to EVEN** (T22 fn. b, IEC 60559) for SINT/INT/DINT/LINT (and per T23 for every integer type including unsigned):
`REAL_TO_INT(1.6)=2, (-1.6)=-2, (1.5)=2, (-1.5)=-2, (1.4)=1, (-1.4)=-1, (2.5)=2, (-2.5)=-2`.
A C cast truncates; `round()` rounds ties away from zero — both wrong. `llrint` under the default FE_TONEAREST mode is right (Kron `KRON_RND`).

⚠️ **TRUNC truncates toward zero** (fn. c): `TRUNC_INT(1.6) = 1`, `TRUNC_INT(-1.6) = -1`.

**BCD** (fn. d): between BYTE/WORD/DWORD/LWORD and USINT/UINT/UDINT/ULINT. `USINT_TO_BCD_BYTE(25) = 2#0010_0101`; `WORD_BCD_TO_UINT(2#0011_0110_1001) = 369`. Validity check: `IS_VALID_BCD` (7.11).

**STRING as a conversion input/output** (fn. e): the text conforms to the **literal syntax** of §6.3 (e.g. a TIME converts to/from `T#…` text) in the §6.1.1 character set.

**Numeric ↔ numeric (§6.6.2.5.3, T23).** Conceptually: widen the source to the largest type of its category, convert to the largest type of the target's category, then narrow to the target. ⚠️ **If the value does not fit, the result is *impl*** (Kron must define it: note that in C an out-of-range float → int conversion is **undefined behaviour**, so it must be clamped or otherwise defined explicitly — `-fwrapv` does not cover it). Example: `REAL_TO_INT(70_000.4)` → LREAL 70000.4 → LINT 70000 → INT *impl*. **BOOL as a source** = an unsigned 0/1.

| Value preserving | Possible loss of accuracy | Range errors → *impl* |
|---|---|---|
| REAL→LREAL; SINT→INT, DINT, LINT, REAL, LREAL; INT→DINT, LINT, REAL, LREAL; DINT→LINT, LREAL; USINT→every wider signed/unsigned and REAL/LREAL (incl. INT); UINT→DINT, LINT, UDINT, ULINT, REAL, LREAL; UDINT→LINT, ULINT, LREAL | LINT→REAL/LREAL; DINT→REAL; ULINT→REAL/LREAL; UDINT→REAL | every narrowing and every signed↔unsigned change (incl. `SINT_TO_USINT`, `USINT_TO_SINT`); float→int (with rounding) |

**Bit string ↔ bit string (§6.6.2.5.4, T24) — BINARY transfer:**
- smaller → larger: into the **rightmost** bytes, leftmost bytes **zero**; larger → smaller: the **rightmost** bytes are kept.
- `LWORD/DWORD/WORD/BYTE_TO_BOOL` = the rightmost bit. `BOOL_TO_BYTE/WORD/DWORD/LWORD` = 16#0 or 16#1.
- `BYTE_TO_CHAR`, `CHAR_TO_BYTE`, `WCHAR_TO_WORD` = binary; `CHAR_TO_WORD/DWORD/LWORD`, `WCHAR_TO_DWORD/LWORD` = zero-extended.

**Bit string ↔ numeric (§6.6.2.5.5, T25) — ⚠️ also BINARY transfer, i.e. bit reinterpretation, NOT value conversion:**
- Same width: pure reinterpretation — `WORD_TO_INT(16#FFFF) = -1`, `INT_TO_WORD(-1) = 16#FFFF`, `DWORD_TO_DINT`, `LWORD_TO_LINT/ULINT`, `BYTE_TO_SINT/USINT`.
- ⚠️ **`DWORD_TO_REAL`, `REAL_TO_DWORD`, `LWORD_TO_LREAL`, `LREAL_TO_LWORD` reinterpret the IEEE-754 bit pattern** (memcpy/union) — `REAL_TO_DWORD(1.0) = 16#3F80_0000`, not 1.
- Widening: into the rightmost bytes, **rest = 0 — no sign extension**: `SINT_TO_WORD(18) = 16#0012`, `INT_TO_DWORD(-1) = 16#0000_FFFF`, `DINT_TO_LWORD(-1) = 16#0000_0000_FFFF_FFFF`; `BYTE_TO_INT(16#FF) = 255`.
- Narrowing: the rightmost bytes: `WORD 16#1234 → SINT` = 16#34 (the PDF's "54" is a typo for 52, §17).
- `BOOL_TO_<integer>` = 0 or 1.
- No BYTE/WORD ↔ REAL/LREAL and no DWORD ↔ LREAL conversion exists.

**Date and time (§6.6.2.5.6, T26):** `LTIME_TO_TIME`, `TIME_TO_LTIME` (range/precision *impl*); `LDT_TO_DT`; `LDT_TO_DATE` (date part); `LDT_TO_LTOD`; `LDT_TO_TOD` (time-of-day part, precision may drop); `DT_TO_LDT`; `DT_TO_DATE`; `DT_TO_LTOD`; `DT_TO_TOD`; `LTOD_TO_TOD`; `TOD_TO_LTOD`. Example: `DT_TO_TOD(DT#1986-04-28-08:40:00) = TOD#08:40:00`, `DT_TO_DATE(...) = DATE#1986-04-28`.

**Characters (§6.6.2.5.7, T27):** `WSTRING_TO_STRING` (characters the impl cannot represent: *impl*); ⚠️ `WSTRING_TO_WCHAR` / `STRING_TO_CHAR` = the **first** character, **empty string → undefined result** (must not read past the end); `STRING_TO_WSTRING` (to UTF-16); `WCHAR_TO_WSTRING` / `CHAR_TO_STRING` = a 1-character string; `WCHAR_TO_CHAR`; `CHAR_TO_WCHAR`.

### 7.5 Numerical functions (§6.6.2.5.8, T28, T29)
- One-argument functions are **overloaded on the given generic, may be typed, and input type = output type**: `ABS` (ANY_NUM) · `SQRT`, `LN`, `LOG` (base 10), `EXP`, `SIN`, `COS`, `TAN` (radians), `ASIN`, `ACOS`, `ATAN` (principal values) (ANY_REAL) · `ATAN2(Y, X)` (ANY_REAL; **pins `Y` then `X`**; positive counter-clockwise, upper half-plane y>0; negative lower half-plane).
- ⚠️ Input type = output type ⇒ `SIN(REAL)` is REAL, `SQRT(REAL)` is REAL (not LREAL).
- The accuracy of numerical functions is *impl* (to be documented).
- ⚠️ **ERROR if the result exceeds the output type's range, or on division by zero** (`ABS(INT#-32768)` overflows).

**Arithmetic (T29):**

| Name | Symbol | Inputs | Definition |
|---|---|---|---|
| `ADD` | `+` | extensible, **ANY_MAGNITUDE** (fn. c — includes TIME) | `OUT := IN1 + IN2 + … + INn` |
| `MUL` | `*` | extensible, ANY_NUM (TIME scaling is T35) | `OUT := IN1 * … * INn` |
| `SUB` | `-` | ANY_MAGNITUDE | `OUT := IN1 - IN2` |
| `DIV` | `/` | ANY_NUM | `OUT := IN1 / IN2`; ⚠️ **integer division truncates toward zero, result of the same type**: `7/3 = 2`, `(-7)/3 = -2` (fn. d) |
| `MOD` | `MOD` (ST keyword) | **ANY_INT only** | ⚠️ `IF IN2 = 0 THEN OUT := 0; ELSE OUT := IN1 - (IN1/IN2)*IN2; END_IF` — **sign follows the dividend** (= C `%`), and **`x MOD 0 = 0` by definition** (not an error) (fn. e) |
| `EXPT` | `**` | ⚠️ **IN1 ANY_REAL, IN2 ANY_NUM, OUT = type of IN1** (fn. f) | `OUT := IN1 ** IN2` |
| `MOVE` | `:=` | exactly one input `IN` (ANY), one output `OUT` (ANY) | `OUT := IN` |

### 7.6 Bit-string functions (§6.6.2.5.9, T30, T31)
- `SHL(IN, N)`, `SHR(IN, N)`, `ROL(IN, N)`, `ROR(IN, N)` — IN: ANY_BIT, N: ANY_INT; overloaded on all bit-string types, typable. SHL: zero-fill on the right. ⚠️ **SHR: zero-fill on the LEFT (logical shift, never arithmetic).** ROL/ROR: circular.
  Example (BYTE `2#0001_1001`, N=3): `SHL = 2#1100_1000`, `SHR = 2#0000_0011`, `ROL = 2#1100_1000`, `ROR = 2#0010_0011`.
- ⚠️ **It is an ERROR if N < 0** (T30 fn. a). BOOL as IN "does not make sense". N ≥ width: not specified (*impl*) — logically SHL/SHR give 0 and ROL/ROR are circular (rotating by the width returns IN).
- `AND` (`&`), `OR`, `XOR`, `NOT`: **extensible except NOT**, overloaded on all bit-string types (BOOL included), typable. Only `&` is also a textual operator symbol; the graphical symbols `>=1` (OR) and `=2k+1` (XOR) are not usable in text (T31 notes 1–2). On a multi-bit type they are bitwise; NOT is the one's complement within the type's width.

### 7.7 Selection (§6.6.2.5.10, T32) — overloaded on ALL data types
| Function | Definition |
|---|---|
| `MOVE(IN)` | `OUT := IN` |
| `SEL(G, IN0, IN1)` | `OUT := IN0` if `G = 0`, `IN1` if `G = 1`; G is BOOL. `SEL(G := 0, IN0 := X, IN1 := 5)` = X |
| `MAX(IN1, …, INn)` / `MIN(…)` | extensible, ANY_ELEMENTARY |
| `LIMIT(MN, IN, MX)` | `OUT := MIN(MAX(IN, MN), MX)` — graphical pin order **MN, IN, MX**; call with formal names (see §17 for the non-formal order conflict) |
| `MUX(K, IN0, …, INn-1)` | selects input number K; ⚠️ **unnamed data inputs are `IN0…INn-1` (0-based)**; typed `MUX_*_**` (* = K type, ** = data type); `MUX(0, B, C, D)` = B; ⚠️ **ERROR if K is outside 0..n−1**; selection among user-defined types optional (fn. d) |

### 7.8 Comparison (§6.6.2.5.10, T33)
- `GT` (`>`), `GE` (`>=`), `EQ` (`=`), `LE` (`<=`), `LT` (`<`): extensible, ANY_ELEMENTARY → BOOL, defined as a chain: `GT(A, B, C) = (A > B) & (B > C)`. `NE` (`<>`) is **not** extensible.
- ⚠️ **Bit strings compare as unsigned integers**, bit by bit from the left, the shorter one zero-padded on the left.
- All six symbols are textual operators. Comparisons may also be defined per language (e.g. LD compare contacts, §12).

### 7.9 Character strings (§6.6.2.5.11, T34)
- ⚠️ **The comparisons of T33 apply to strings**, including ordering: the shorter string is padded on the right with code-0 characters and compared left to right by character code. `'Z' > 'AZ'`, `'AZ' > 'ABC'`. CHAR/WCHAR may stand for a 1-character string.
- ⚠️ **Character positions are 1-based** (1 … L).

| Function | Pins (in order) | Result | Example |
|---|---|---|---|
| `LEN` | `IN` | ANY_INT | `LEN('ASTRING') = 7` |
| `LEFT` | `IN, L` | leftmost L chars | `LEFT(IN := 'ASTR', L := 3) = 'AST'` |
| `RIGHT` | `IN, L` | rightmost L chars | `RIGHT(IN := 'ASTR', L := 3) = 'STR'` |
| `MID` | `IN, L, P` ⚠️ **L before P** | L chars from position P | `MID(IN := 'ASTR', L := 2, P := 2) = 'ST'` |
| `CONCAT` | extensible, ANY_CHARS | | `CONCAT('AB', 'CD', 'E') = 'ABCDE'` |
| `INSERT` | `IN1, IN2, P` | IN2 inserted **after** position P | `INSERT(IN1 := 'ABC', IN2 := 'XY', P := 2) = 'ABXYC'` |
| `DELETE` | `IN, L, P` | removes L chars from P | `DELETE(IN := 'ABXYC', L := 2, P := 3) = 'ABC'` |
| `REPLACE` | `IN1, IN2, L, P` | replaces L chars of IN1 from P by IN2 | `REPLACE(IN1 := 'ABCDE', IN2 := 'X', L := 2, P := 3) = 'ABXE'` |
| `FIND` | `IN1, IN2` | 1-based position of the first IN2 in IN1, **0 if absent** | `FIND(IN1 := 'ABCBC', IN2 := 'BC') = 2` |

CONCAT inputs and IN2 of INSERT/REPLACE/FIND may be CHAR/WCHAR.
⚠️ **Errors:** an ANY_INT input < 0; access to a non-existent character position; a result longer than the impl max length; mixing STRING/CHAR with WSTRING/WCHAR in one call.

### 7.10 Date and duration functions (§6.6.2.5.12, T35, T36)
T35 — operators allowed on time types (overloaded **only within** {TIME, DT, DATE, TOD} or within {LTIME, LDT, LDATE, LTOD}):

| Operation | IN1 | IN2 | OUT | Typed name |
|---|---|---|---|---|
| `+` | TIME | TIME | TIME | `ADD_TIME` (`ADD_LTIME`) |
| `+` | TOD | TIME | TOD | `ADD_TOD_TIME` (`ADD_LTOD_LTIME`) |
| `+` | DT | TIME | DT | `ADD_DT_TIME` (`ADD_LDT_LTIME`) |
| `-` | TIME | TIME | TIME | `SUB_TIME` (`SUB_LTIME`) |
| `-` | DATE | DATE | TIME | `SUB_DATE_DATE` (`SUB_LDATE_LDATE` → LTIME) |
| `-` | TOD | TIME | TOD | `SUB_TOD_TIME` (`SUB_LTOD_LTIME`) |
| `-` | TOD | TOD | TIME | `SUB_TOD_TOD` (LTOD − LTOD → LTIME) |
| `-` | DT | TIME | DT | `SUB_DT_TIME` (`SUB_LDT_LTIME`) |
| `-` | DT | DT | TIME | `SUB_DT_DT` (`SUB_LDT_LDT`) |
| `*` | TIME | ANY_NUM | TIME | `MUL_TIME` (`MUL_LTIME`) |
| `/` | TIME | ANY_NUM | TIME | `DIV_TIME` (`DIV_LTIME`) |

Not defined (must be a type error): `DATE + TIME`, `TIME * TIME`, `TIME / TIME`, `TIME + number`. ⚠️ An out-of-range result is an **error**.

T36: `CONCAT_DATE_TOD(DATE, TOD) → DT`, `CONCAT_DATE_LTOD → LDT`, `CONCAT_DATE(YEAR, MONTH, DAY) → DATE`, `CONCAT_TOD(HOUR, MINUTE, SECOND, MILLISECOND) → TOD`, `CONCAT_LTOD(…) → LTOD`, `CONCAT_DT(YEAR, MONTH, DAY, HOUR, MINUTE, SECOND, MILLISECOND) → DT`, `CONCAT_LDT(…)`; `SPLIT_DATE(IN, YEAR, MONTH, DAY)`, `SPLIT_TOD(IN, HOUR, MINUTE, SECOND, MILLISECOND)`, `SPLIT_LTOD`, `SPLIT_DT(IN, YEAR … MILLISECOND)`, `SPLIT_LDT` (outputs); ⚠️ **`DAY_OF_WEEK(IN : DATE)` → 0 = Sunday, 1 = Monday … 6 = Saturday**. YEAR is at least 16 bits; the output integer types are *impl*; extra µs/ns pins may be added. Out-of-range result = error.

### 7.11 Endianness, enums, validity (§6.6.2.5.13–15, T37–T39)
- `TO_BIG_ENDIAN`, `TO_LITTLE_ENDIAN`, `FROM_BIG_ENDIAN`, `FROM_LITTLE_ENDIAN` (IN : ANY → the same type). Converted: ANY_INT ≥ 16 bit, ANY_BIT ≥ 16 bit, ANY_REAL, WCHAR, TIME, arrays and structs of these (other members are left untouched). A no-op if already in the requested order. ⚠️ **Bit 0 is always the rightmost (least significant) bit, and partial access `.%B0` is always the low part, regardless of endianness.**
- Enumerations (T38): only `SEL`, `MUX`, `EQ` (`=`), `NE` (`<>`) apply. ⚠️ **No ordering (`<`, `>`) and no arithmetic on enumerated values** (named-value types excepted, §4.4).
- `IS_VALID(ANY_REAL) : BOOL` — FALSE for NaN, +Inf, −Inf. `IS_VALID_BCD(ANY_BIT) : BOOL` — FALSE if any nibble is not BCD. Further types *impl*.

## 8. Function blocks (§6.6.3)

### 8.1 Type declaration (§6.6.3.2, T40)
- `FUNCTION_BLOCK name … END_FUNCTION_BLOCK`. Sections as for functions, plus: ⚠️ **`VAR` is STATIC** (persists between calls), `VAR_TEMP` is temporary (re-initialised every call).
- VAR_EXTERNAL modifiable, VAR_EXTERNAL CONSTANT not. Variable-length arrays only as VAR_IN_OUT.
- Inputs, outputs, statics and temporaries may be initialised (`VAR B : REAL := 12.1;`, `VAR_TEMP I : INT := 1;`).
- Static variables may be `PUBLIC` or `PRIVATE` (**PRIVATE by default**); a PUBLIC static is readable from outside like an output (`inst.var`).
- RETAIN / NON_RETAIN on VAR_INPUT, VAR_OUTPUT, VAR and local FB instances (T40 4a–5b).
- ⚠️ **Edge inputs**: `VAR_INPUT X : BOOL R_EDGE; Y : BOOL F_EDGE; END_VAR` implicitly declares an R_TRIG/F_TRIG; inside the body `X` reads as the edge pulse. Equivalent expansion (§6.6.3.2 ex. 3): `X_TRIG(CLK := X); Y_TRIG(CLK := Y); Z := X_TRIG.Q AND Y_TRIG.Q;`. Graphical form: `>` / `<` at the input.
- Partly located `%I*` allowed in internal variables.
- Instances of FBs/classes may be declared in **every section except VAR_TEMP** (and not in CONSTANT sections). An FB instance should not share its name with a function in scope (rule 18).

### 8.2 Instance declaration (§6.6.3.3, T41)
`T1, T2, T3 : TON;` · `TempLoop : PID := (PropBand := 2.5, Integral := T#5s);` — the parenthesised list initialises inputs, outputs and PUBLIC variables; unlisted ones keep the type defaults.

### 8.3 Call (§6.6.3.4, T42)
1. Textual: instance name + parameter list: `CMD_TMR(IN := bIn1, PT := T#300ms);` then `A := CMD_TMR.Q;`.
2. Graphical: the instance name is written **above** the block.
3. Inputs and outputs are **stored** and accessible like struct members:
   - a) assigned within the call (typical);
   - b) ⚠️ assigned **separately** (`YourTon.IN := r;`) — **takes effect at the NEXT call**;
   - c) ⚠️ **inputs not assigned keep their initial value or the value from the LAST call** (unlike functions).
- An in-out or FB-instance input with no actual parameter must already hold a valid stored value before the body uses it, otherwise it is a **run-time error**.
4. Called with EN = 0: the Implementer specifies whether inputs/in-outs are set in the instance.
5. An FB instance may be passed as VAR_INPUT or VAR_IN_OUT of another FB.
6. ⚠️ Outputs of an instance passed in via VAR_INPUT / VAR_IN_OUT / VAR_EXTERNAL can be **read but not modified** inside.
7. An instance passed via VAR_IN_OUT or VAR_EXTERNAL **may be called** inside; one passed via VAR_INPUT may not (F14 note: that would modify it).
8. ⚠️ **Only variables or FB instance names may be passed to a VAR_IN_OUT** (never an expression or literal); cascading in-outs is allowed.

T42 forms: complete formal `YourCTU(EN := NOT B, CU := r, PV := c1, ENO => next, Q => out, CV => c2)`; incomplete `YourCTU(Q => out, CV => c2)` (EN, CU, PV keep their stored values); negated `NOT Q => out` and `EN := NOT (a <> b)`; separate input assignment then `YourTon(NOT Q => out)`; output read after the call `x := FB_Instance.Output`; instance arrays `TONs[i](IN := bIn1, PT := T#20ms)`; instance as a struct member `myCooler.Cooling(IN := bIn1, PT := T#30s)`; `VAR_IN_OUT IO_TMR : TOF;` → `IO_TMR(IN := A_VAR, PT := T#10S); EXPIRED := IO_TMR.Q;`; same through `VAR_EXTERNAL`.

### 8.4 Usage rules for FB parameters (F13/F14) — `FB_INST : FB_TYPE` with `In`, `Out`, `In_out`, internal `M`

| | Inside the FB body | Outside the FB |
|---|---|---|
| 1 read input | `M := In;` ✅ | `A := FB_INST.In;` ❌ |
| 2 assign input | `In := M;` ❌ | `FB_INST(In := A);` ✅ · `FB_INST.In := A;` ✅ (effective next call) |
| 3 read output | `M := Out;` ✅ | `FB_INST(Out => B);` ✅ · `B := FB_INST.Out;` ✅ |
| 4 assign output | `Out := M;` ✅ | `FB_INST.Out := B;` ❌ |
| 5 read in-out | `M := In_out;` ✅ | `FB_INST(In_out => C);` ❌ · `C := FB_INST.In_out;` ❌ |
| 6 assign in-out | `In_out := M;` ✅ | `FB_INST(In_out := C);` ✅ · `FB_INST.In_out := C;` ❌ |

❌ = not allowed (unpredictable *impl* effects); the transpiler/validator should reject them. Debugger/HMI/communication access is outside these rules (F13 note 2) — Kron's write mailbox is that channel.

### 8.5 Standard function blocks (§6.6.3.5) — exact bodies
The Implementer may add more; standard FBs may be overloaded/extensible.

**Bistables (T43).** Initial `Q1 = FALSE` (fn. a).
- `SR(S1, R) → Q1` — **set dominant**: `Q1 := S1 OR (NOT R AND Q1);` (long names `SET1`, `RESET`).
- `RS(S, R1) → Q1` — **reset dominant**: `Q1 := NOT R1 AND (S OR Q1);` (long names `SET`, `RESET1`).

**Edge detection (T44)** — Q is TRUE for exactly ONE execution:
```
FUNCTION_BLOCK R_TRIG  VAR_INPUT CLK: BOOL; END_VAR  VAR_OUTPUT Q: BOOL; END_VAR  VAR M: BOOL; END_VAR
  Q := CLK AND NOT M;   M := CLK;
FUNCTION_BLOCK F_TRIG  (same interface)
  Q := NOT CLK AND NOT M;   M := NOT CLK;
```
⚠️ With `M` initially FALSE: an R_TRIG whose CLK is TRUE at the first execution after a cold restart gives `Q = TRUE` once; ⚠️ **an F_TRIG whose CLK is FALSE (or unconnected) also gives `Q = TRUE` on its first execution** (T44 note) — this is the standard behaviour, not a bug.

**Counters (T45)** — `CU`/`CD` are `R_EDGE` inputs (edges evaluated inside the block); PVmin/PVmax are *impl* (natural choice: the CV type's limits, i.e. the counter **saturates, never wraps**):
```
CTU (CU R_EDGE, R, PV) → Q, CV:
  IF R THEN CV := 0;
  ELSIF CU AND (CV < PVmax) THEN CV := CV + 1;
  END_IF;
  Q := (CV >= PV);

CTD (CD R_EDGE, LD, PV) → Q, CV:
  IF LD THEN CV := PV;
  ELSIF CD AND (CV > PVmin) THEN CV := CV - 1;
  END_IF;
  Q := (CV <= 0);

CTUD (CU, CD R_EDGE, R, LD, PV) → QU, QD, CV:
  IF R THEN CV := 0;                         (* R beats LD *)
  ELSIF LD THEN CV := PV;
  ELSE
    IF NOT (CU AND CD) THEN                  (* simultaneous edges: no change *)
      IF CU AND (CV < PVmax) THEN CV := CV + 1;
      ELSIF CD AND (CV > PVmin) THEN CV := CV - 1;
      END_IF;
    END_IF;
  END_IF;
  QU := (CV >= PV);
  QD := (CV <= 0);
```
Typed variants: `CTU_INT` (= `CTU`), `CTU_DINT`, `CTU_LINT`, `CTU_UDINT`, `CTU_ULINT`; same for `CTD_*` and `CTUD_*` (PV and CV of that type). Note `QD := (CV <= 0)` and `Q := (CV <= 0)` for CTD — the down-counters compare with 0, not PVmin.

**Timers (T46, F15)** — `TP`, `TON`, `TOF` (overloaded), `TP_TIME`/`TON_TIME`/`TOF_TIME`, `TP_LTIME`/`TON_LTIME`/`TOF_LTIME`; pins `IN : BOOL`, `PT : TIME`, `Q : BOOL`, `ET : TIME`. The graphical aliases `T---0` (TON) and `0---T` (TOF) shall not be used in text (fn. a). ⚠️ The effect of changing PT while timing (e.g. PT := T#0s to cancel a TP) is *impl* and must be documented.

Timing diagrams (F15, read from the rendered page):
- **TP (pulse):** a rising edge of IN sets `Q := TRUE` for exactly PT. ⚠️ **Edges of IN during the pulse are ignored (not retriggerable).** ET ramps 0 → PT during the pulse, then **holds PT while IN is still TRUE**, and returns to 0 when the pulse has ended **and** IN is FALSE. A short IN pulse still yields a full PT output pulse; ET resets at the end of that pulse.
- **TON (on-delay):** `Q := TRUE` once IN has been TRUE **continuously** for PT; Q falls **immediately** with IN. ET ramps from the rising edge, stops at PT, and resets to 0 when IN falls (if IN falls before PT, ET → 0 and Q never rises).
- **TOF (off-delay):** `Q := TRUE` **immediately** with IN; ET = 0 while IN is TRUE; on the falling edge ET ramps and Q falls when ET reaches PT; ET holds PT while IN stays FALSE; IN rising again before PT keeps Q TRUE and resets ET to 0.

Kron note (`src/services/CLAUDE.md`): the task interval bounds every timer — the observed timing quantises to the scan.

**Communication FBs** (§6.6.3.5.6) are defined in IEC 61131-5, not here.

## 10. Structured Text (§7.3)

### 10.1 Expressions (§7.3.2)
- An operand is a literal, an enumerated value, a variable, a call of a function/method/FB **with a result**, or another expression. Max expression length *impl*. The Implementer **shall define** the implicit and explicit conversions (Kron: F11/F12 as in §6.6 above).
- **Evaluation rules:**
  1. higher precedence first: with A,B,C,D = 1,2,3,4: `A+B-C*ABS(D) = -9`, `(A+B-C)*ABS(D) = 0`;
  2. ⚠️ **equal precedence: left to right** — `A+B+C = (A+B)+C`, and therefore `A**B**C = (A**B)**C`;
  3. ⚠️ **the LEFT operand is evaluated first**: in `SIN(A)*COS(B)` SIN runs before COS. **C does not specify operand evaluation order** — any operand with a side effect (FB call, function with in-out/external writes) must be sequenced into a temporary first;
  4. Boolean expressions **may** be short-circuited; the extent is *impl* (document: C's `&&`/`||` short-circuit, so a function call on the right of AND may not run);
  5. functions and methods are called inside expressions;
  6. overloaded operators convert operands per §6.6.1.7.
- ⚠️ **Errors:** division by zero; operands of the wrong type; **a numeric result outside its type's range** (overflow).

**Operator precedence (T71), highest first** — the authoritative ordering together with the Annex A grammar (§10.2):

| Prec. | Operator | Symbol | Notes |
|---|---|---|---|
| 11 | parentheses | `(expr)` | |
| 10 | function / method call | `F(args)` | |
| 9 | dereference | `^` | |
| 8 | ⚠️ **negation, unary plus, complement** | `-`, `+`, `NOT` | binds tighter than `**` |
| 7 | exponentiation | `**` | ≡ `EXPT(A, B)` (fn. b) — base must be ANY_REAL |
| 6 | multiply, divide, modulo | `*` `/` `MOD` | |
| 5 | add, subtract | `+` `-` | |
| 4 | comparison, equality | `<` `>` `<=` `>=` `=` `<>` | grammar refines: relational above equality (§10.2) |
| 3 | Boolean AND | `&` `AND` | |
| 2 | exclusive OR | `XOR` | |
| 1 | OR | `OR` | lowest |

Consequences: ⚠️ **`-A**2` = `(-A)**2`**; ⚠️ **`NOT A = B` = `(NOT A) = B`**; `A AND B OR C AND D` = `(A AND B) OR (C AND D)`; `A OR B XOR C` = `A OR (B XOR C)`. The operands of each operator follow the rules of the corresponding standard function's inputs (fn. a): `+` is ADD, `**` is EXPT, etc. T71 lists `A < B < C` as a comparison example; it parses as `(A<B)<C`, which compares a BOOL with C — a type error unless C is BOOL (Kron rejects chains outright, see §16).

### 10.2 Normative grammar for expressions (Annex A)
```
Expression    : Xor_Expr ( 'OR' Xor_Expr )*
Xor_Expr      : And_Expr ( 'XOR' And_Expr )*
And_Expr      : Compare_Expr ( ( '&' | 'AND' ) Compare_Expr )*
Compare_Expr  : Equ_Expr ( ( '=' | '<>' ) Equ_Expr )*
Equ_Expr      : Add_Expr ( ( '<' | '>' | '<=' | '>=' ) Add_Expr )*
Add_Expr      : Term ( ( '+' | '-' ) Term )*
Term          : Power_Expr ( ( '*' | '/' | 'MOD' ) Power_Expr )*
Power_Expr    : Unary_Expr ( '**' Unary_Expr )*
Unary_Expr    : ( '-' | '+' | 'NOT' )? Primary_Expr
Primary_Expr  : Constant | Enum_Value | Variable_Access | Func_Call | Ref_Value | '(' Expression ')'
Variable_Access : Variable Multibit_Part_Access?        (* x.3, x.%X3, x.%B1 *)
Func_Call     : Func_Access '(' ( Param_Assign ( ',' Param_Assign )* )? ')'
Param_Assign  : ( ( Variable_Name ':=' )? Expression ) | Ref_Assign | ( 'NOT'? Variable_Name '=>' Variable )
Constant_Expr : Expression   (* must evaluate to a constant at compile time *)
```
- ⚠️ **Relational (`< > <= >=`) binds tighter than equality (`= <>`)**: `a < b = c < d` is `(a < b) = (c < d)`.
- ⚠️ `**` is left-associative and **its operands are unary expressions**: `2 ** -1` is legal, `-2 ** 2` = `(-2) ** 2` = 4.
- **One** unary operator per operand in the grammar: `- -a` and `NOT NOT a` need parentheses (strict reading).
- All binary operators are left-associative.

### 10.3 Statements (§7.3.3, T72, Annex A)
```
Stmt_List     : ( Stmt? ';' )*                              ⚠️ every statement ends with ';' — including END_IF; END_CASE; END_FOR; …
Assign_Stmt   : Variable ':=' Expression | Ref_Assign | Assignment_Attempt
Subprog_Ctrl  : Func_Call | Invocation | 'SUPER' '(' ')' | 'RETURN'
IF_Stmt       : 'IF' Expression 'THEN' Stmt_List ( 'ELSIF' Expression 'THEN' Stmt_List )* ( 'ELSE' Stmt_List )? 'END_IF'
Case_Stmt     : 'CASE' Expression 'OF' ( Case_List ':' Stmt_List )+ ( 'ELSE' Stmt_List )? 'END_CASE'
Case_List_Elem: Subrange | Constant_Expr
For_Stmt      : 'FOR' Control_Variable ':=' Expression 'TO' Expression ( 'BY' Expression )? 'DO' Stmt_List 'END_FOR'
Control_Variable : Identifier                                 (* a plain variable — no array element / member *)
While_Stmt    : 'WHILE' Expression 'DO' Stmt_List 'END_WHILE'
Repeat_Stmt   : 'REPEAT' Stmt_List 'UNTIL' Expression 'END_REPEAT'
Iteration     : … | 'EXIT' | 'CONTINUE'
```
(If Kron accepts a missing `;` after `END_IF`, that is an extension — fine, but document it.)

**T72 features:** 1a `A := B; CV := CV+1; C := SIN(X);` · 1b `A_Real := B_Int;` (implicit per F11) · 1c `A_Struct1 := B_Struct1; C_Array1 := D_Array1;` · 1d ⚠️ **`A_Instance1 := B_Instance1;` (FB instance assignment is a standard feature)** · 2a `FCT(17);` · 2b FB call + output use · 2c method call · 3 `RETURN;` · 4 IF · 5 CASE · 6 FOR · 7 WHILE · 8 REPEAT · 9 CONTINUE · 10 EXIT · 11 empty statement `;`. Fn. a: **if EXIT/CONTINUE are supported, they are supported in ALL loop kinds.** Fn. b: a result of a call used as a statement is discarded.

### 10.4 Assignment, comparison, result, call (§7.3.3.2)
- Assignment: `A := B` if same type or B implicitly convertible. Multi-element variables (arrays, structs) must have the **same** type; every element is copied.
- ⚠️ **Comparison of multi-element variables is a standard feature**: `A = B` on two arrays/structs of the same type compares element by element (§7.3.3.2.2).
- **Result** (§7.3.3.2.3): a POU with a result must contain **at least one assignment to its own name**; the returned value is the **most recent** such assignment. ⚠️ **It is an ERROR to return (with ENO TRUE or without ENO) when no such assignment has been executed** — the transpiler must diagnose a function whose result may be unassigned on some path (at least warn when no assignment exists at all).
- **RETURN**: early exit from a function, FB or program.

### 10.5 IF / CASE (§7.3.3.3)
- IF executes a branch when its condition evaluates to **1 (TRUE)** — conditions are BOOL.
- CASE: the **selector is an expression of an elementary type**; each statement group is labelled by one or more **literals, enumerated values, subranges** (`6..10`) or constant expressions, comma separated (`1,5:`, `4,6..10:`); labels must be comparable with the selector. ⚠️ **The FIRST group whose label set contains the selector value executes**; no match → ELSE (if any), else nothing. Overlapping labels are therefore legal with first-match semantics (a C `switch` rejects duplicate labels — emit an if-chain or reject overlap loudly). Max number of selections *impl*.

### 10.6 Loops (§7.3.3.4)
- ⚠️ **WHILE and REPEAT shall not be used as wait loops for an externally determined condition** (use SFC); **it is an ERROR to use them where termination (or an EXIT) cannot be guaranteed** — in a scan-cycle PLC a non-terminating loop stalls the task.
- **FOR** (§7.3.3.4.2): ⚠️ the control variable, the initial value and the final value are **expressions of the SAME integer type** (SINT, INT, DINT, …), and ⚠️ **the control variable shall NOT be altered by the loop body** (an assignment to it inside the loop must be rejected). BY defaults to 1. The termination test is made at the **start** of each iteration: the body does not run if the control variable is already beyond the final value (greater for a positive step, smaller for a negative one). ⚠️ **The value of the control variable after the loop is *impl*** (document it). Example: `FOR I := 3 TO 1 BY -1 DO …` terminates when I reaches 0. A `BY 0` step would never terminate — reject a constant 0 step. FOR is meant for loops whose count is known in advance.
- **WHILE**: test first; may run zero times. **REPEAT**: runs at least once, until the condition is TRUE.
- **CONTINUE**: jump to just before the terminator of the innermost loop. Example: nested `FOR I := 1 TO 3 / FOR J := 1 TO 2` with `SUM := SUM+1; IF FLAG THEN CONTINUE; END_IF; SUM := SUM+1;` inside and `SUM := SUM+1` after the inner loop → **SUM = 15 if FLAG = 0, 9 if FLAG = 1**.
- **EXIT**: leave the **innermost** loop only; control passes to the statement after its terminator. Same example with EXIT → **SUM = 15 if FLAG = 0, 6 if FLAG = 1**. (Use these two examples as transpiler tests.)

## 11. Configuration, resources, tasks (§6.8)

### 11.1 Software model (§4.1)
Configuration ⊃ resources ⊃ tasks + programs. ⚠️ **Starting a configuration initialises its globals, then starts its resources; starting a resource initialises all its variables, then enables its tasks. Stopping a resource disables its tasks.** Globals are shared between programs via VAR_GLOBAL / VAR_EXTERNAL (§4.2).

### 11.2 Textual configuration (§6.8.1, T62, F28)
```
CONFIGURATION CELL_1
  VAR_GLOBAL w : UINT; END_VAR
  RESOURCE STATION_1 ON PROCESSOR_TYPE_1
    VAR_GLOBAL z1 : BYTE; END_VAR
    TASK SLOW_1 (INTERVAL := t#20ms, PRIORITY := 2);
    TASK FAST_1 (INTERVAL := t#10ms, PRIORITY := 1);
    PROGRAM P1 WITH SLOW_1 : F(x1 := %IX1.1);
    PROGRAM P2 : G(OUT1 => w, FB1 WITH SLOW_1, FB2 WITH FAST_1);
  END_RESOURCE
  RESOURCE STATION_2 ON PROCESSOR_TYPE_2
    VAR_GLOBAL z2 : BOOL; AT %QW5 : INT; END_VAR
    TASK PER_2 (INTERVAL := t#50ms, PRIORITY := 2);
    TASK INT_2 (SINGLE := z2, PRIORITY := 1);
    PROGRAM P1 WITH PER_2 : F(x1 := z2, x2 := w);
    PROGRAM P4 WITH INT_2 : H(HOUT1 => %QW5, FB1 WITH PER_2);
  END_RESOURCE
  VAR_ACCESS
    ABLE : STATION_1.%IX1.1 : BOOL READ_ONLY;
    BAKER : STATION_1.P1.x2 : UINT READ_WRITE;
  END_VAR
  VAR_CONFIG
    STATION_1.P1.COUNT : INT := 1;
    STATION_1.P1.TIME1 : TON := (PT := T#2.5s);
    STATION_2.P4.FB1.C2 AT %QB25 : BYTE;
  END_VAR
END_CONFIGURATION
```
- `RESOURCE … ON <type>`: not required with a single resource. Globals are scoped to their configuration/resource.
- Grammar: `TASK name ( [SINGLE := src,] [INTERVAL := src,] PRIORITY := n )` — **PRIORITY is mandatory**; `PROGRAM [RETAIN|NON_RETAIN] inst [WITH task] : Type ( in := src, out => sink, fbInst WITH task )`.
- **VAR_CONFIG**: path `resource.program.fb….var[.member]`; instance-specific values **always override** type-specific ones; **not** allowed on VAR_TEMP, VAR_EXTERNAL, VAR CONSTANT, VAR_IN_OUT variables.
- ⚠️ A VAR_ACCESS type that differs from the variable's declared type is an **error**.

### 11.3 Access paths (§6.8.1)
`name : path : type [READ_WRITE | READ_ONLY]` — **default READ_ONLY**; the path starts at the resource, then program, then FB instances; elements of arrays/structs may be addressed. **No access paths to VAR_TEMP, VAR_EXTERNAL, VAR_IN_OUT.** CONSTANT variables and FB inputs that are connected to other variables must be READ_ONLY. READ_WRITE to an FB output is *impl*. (Kron's REST/HMI write path — the write mailbox — is the practical equivalent; it should respect the same rules: no writes to CONSTANTs.)

### 11.4 Tasks (§6.8.2, T63) — the scheduling contract
A task runs a set of POUs **periodically** or **on the rising edge** of a BOOL. Inputs: `SINGLE : BOOL`, `INTERVAL : TIME`, `PRIORITY : UINT`. Max tasks per resource and interval resolution *impl*.
- a) The POUs are scheduled on **each rising edge of SINGLE**.
- b) If INTERVAL ≠ 0 they are scheduled **periodically** while SINGLE is 0. **INTERVAL = 0 (the default) → no periodic scheduling.**
- c) ⚠️ **PRIORITY 0 is the HIGHEST priority; larger numbers are lower priorities.** Non-preemptive scheduling: when the CPU is free the highest-priority scheduled POU starts; among equals, the one waiting longest. Preemptive scheduling: a POU may interrupt a **lower**-priority one, never one of the same or higher priority. The Implementer **shall** give the user the means to determine whether all deadlines will be met.
- d) ⚠️ **A program with NO task association has the LOWEST priority, is scheduled when its resource starts, and is re-scheduled as soon as it finishes** (free-running background cycle) — T62 feature 6c.
- e) An FB instance associated with a task runs **exclusively** under that task, independently of its containing POU.
- f) An FB instance not associated with a task runs in the normal evaluation order of its POU.
- Class instances cannot be associated with tasks; methods execute in the calling POU.
- g) ⚠️ **Data consistency**: if an FB receives several inputs from another FB, they all come from **the same evaluation** of the source; several FBs in the same task fed by one source see **the same evaluation** of it. The implementation shall buffer the outputs of task-associated POUs as needed (cross-task data must be snapshotted, not read mid-update).
- ⚠️ **It is an ERROR if a task fails to be scheduled or misses its deadline** (overrun) — it must be detected and reported, not silently absorbed.

## 12. Graphical languages: common rules and LD (§8)

### 12.1 Common elements (§8.1)
- All supported data types and instance declarations shall be usable as operands/parameters in the graphical languages: elementary variables, array elements with **constant or variable subscripts** (`Xs[3]`, `Xs[i]`), struct members (`S.x`, `Ss[3].x`), instances as parameters (`t.Q`, `Ts[i].Q`, `S.t`), instance calls of `Ts[i]`, `s.t`, `Ss[i].t`. Using an **expression** as a parameter or subscript is outside the standard.
- Connectors (`>NAME>`) store nothing; ⚠️ **a connector label equal to the name of another element of the POU is an error**. Topology restrictions are *impl* and must be documented.
- A **network** is a maximal set of interconnected elements (excluding the LD rails); a network label (identifier or unsigned integer, followed by `:`) is local to the POU.
- Flow: **LD power flow left → right**; FBD signal flow output → input; SFC activity flow from the bottom of a step through a transition to the top of the next.
- **Network evaluation** (§8.1.5) — the display order need not be the evaluation order, but the result must be equivalent to: a) ⚠️ **no element is evaluated before ALL of its inputs**; b) an element is complete only when all its outputs are evaluated; c) a network is complete only when every element's outputs are evaluated (even with execution control elements); d) networks follow the LD/FBD ordering rules.
- **Feedback** (§8.1.5.2): an output used as an input of an element that precedes it. a) **Explicit loops only in FBD** (in LD feedback is through a variable, e.g. a self-holding contact); b) the user must be able to fix the order inside a loop; c) ⚠️ **feedback variables shall be initialised — an uninitialised feedback variable is an error**; the initial value is used on the first evaluation; d) after its element is evaluated, the new value is used until that element is evaluated again.

### 12.2 Execution control (§8.1.6, T73)
- Jump: a BOOL line ending in `>>LABEL` transfers control when TRUE; an unconditional jump starts at the left rail (LD) or the literal 1 (FBD). ⚠️ **The target is a network label in the same POU body (or the same ACTION).**
- `<RETURN>`: a conditional return when its input is TRUE; the unconditional return is the physical end or a RETURN on the left rail.

### 12.3 Ladder diagram (§8.2)
- **Rails** (§8.2.2): left rail always ON; right rail may be implicit and has no state.
- **Links** (§8.2.3): ON/OFF = 1/0 = power flow. A horizontal link passes the state of the element on its left to the element on its right. ⚠️ **A vertical link is the inclusive OR of the horizontal links on its LEFT side and is copied to all horizontal links on its RIGHT side — never back to the left** (power never flows backwards / right-to-left).
- **Contacts** (§8.2.4, T75) — right link = left link AND f(variable); ⚠️ **a contact never modifies its variable**:

| Symbol | Name | Right link |
|---|---|---|
| `--\| \|--` | normally open | left AND var |
| `--\|/\|--` | normally closed | left AND NOT var |
| `--\|P\|--` | positive transition | ON for **one** evaluation when var goes OFF→ON **while the left link is ON**; OFF otherwise |
| `--\|N\|--` | negative transition | ON for one evaluation when var goes ON→OFF while the left link is ON |
| compare contact, typed | `<op1> <cmp> DT <op2>` | left AND (op1 cmp op2), both operands of type DT |
| compare contact, overloaded | `<op1> <cmp> <op2>` | left AND (op1 cmp op2), §6.6.1.7 rules |

- **Coils** (§8.2.5, T76) — ⚠️ **a coil copies the state of its left link to its right link unchanged**, so a rung may continue after a coil (series coils, coils in parallel branches). Example: `a` coil directly on the left rail is always TRUE; coils `c`, `d` in series after contact `b`, and `e` in a parallel branch, all equal `b`.

| Symbol | Name | Variable |
|---|---|---|
| `--( )--` | coil | := left |
| `--(/)--` | negated coil | := NOT left (right link still = left) |
| `--(S)--` | set (latch) | := TRUE while left is ON; stays set until an (R) coil |
| `--(R)--` | reset (unlatch) | := FALSE while left is ON; stays reset until an (S) coil |
| `--(P)--` | positive transition coil | TRUE for **one** evaluation when the left link goes OFF→ON |
| `--(N)--` | negative transition coil | TRUE for one evaluation when the left link goes ON→OFF |

- **Functions and FBs in LD** (§8.2.6): actual variables may be written outside the block next to the formal name; ⚠️ **every block has at least one BOOL input and one BOOL output** for power flow (EN/ENO for functions).
- ⚠️ **Order of evaluation** (§8.2.7): **networks (rungs) are evaluated top to bottom as displayed**, except where jumps/returns change it. Within a rung, §12.1 a)–c) apply (all inputs of an element before the element).

### 12.4 FBD (§8.3) — not in Kron
Outputs of blocks shall not be wired together (no "wired-OR" — use an OR block); the Implementer provides a way to set the network execution order.

## 13. Features Kron does not implement — key rules (so a future implementation starts correct)

**SFC (§6.7, T54–T61)** — only in FBs and programs; if any part of a POU is SFC, all of it is. Steps: `STEP s: … END_STEP`, exactly **one** `INITIAL_STEP` per network (error otherwise); `s.X` (active flag) and `s.T` (elapsed TIME since activation, holds its value when deactivated, reset to T#0s on activation) — **writing them is an error**. Transitions: `TRANSITION [name] [(PRIORITY := n)] FROM s1 TO s2 := cond; END_TRANSITION`, multiple steps `FROM (a, b) TO (c, d)`; **a transition condition with side effects is an error**. Actions: `ACTION a: … END_ACTION`, qualifiers N, R, S, L, D, P, SD, DS, SL, P1, P0 (L/D/SD/DS/SL need a TIME); action control equivalent to the ACTION_CONTROL FB (F22/F23), with or without "final scan" (T60, pick one). Evolution: a transition is **enabled** when all preceding steps are active and **cleared** when enabled and TRUE; clearing deactivates all predecessors then activates all successors; steps and transitions always alternate; successor conditions are not tested until the effects of a step's activation have propagated (a step lives ≥ 1 scan); simultaneous divergence/convergence use double lines; **non-prioritised selection branches that can be TRUE together are an error** (use `*` left-to-right priority, numbered priority, or mutually exclusive conditions); unsafe (token proliferation) and unreachable (deadlock) SFCs shall be treated as errors. Action indicator variables are deprecated.

**OOP (§6.6.5–6.6.8)** — CLASS (VAR sections only, no body, not callable), METHOD (all variables temporary; result assigned to the method name; method outputs only usable in the call itself — `x := I.out` and `I.in := a` are errors), access PUBLIC/PRIVATE/INTERNAL/PROTECTED (default PROTECTED), single inheritance `EXTENDS`, `OVERRIDE` (same signature and access), `FINAL`, `ABSTRACT`, `THIS`, `SUPER`, `SUPER()` (base FB body, once, not in a loop, only in the body), `INTERFACE` with `IMPLEMENTS` (multiple), interface variables are references initialised to NULL (**use before assignment = run-time error**), assignment attempt `?=` (result NULL on failure, must be checked), dynamic binding through interfaces, VAR_IN_OUT of a base type and references. Interfaces and references shall not be in-out variables.

**Namespaces (§6.9)** — `NAMESPACE [INTERNAL] A.B … END_NAMESPACE`, public by default, `INTERNAL` elements, qualified access `A.B.elem`, `USING A.B;` (does not import nested namespaces). Standard functions/FBs live in the global namespace.

**IL (§7.2)** — deprecated; do not implement.

## 14. Errors the standard requires to be detected (checklist)

Compile time (the transpiler/validator must reject, with `POU, line/rung`):
- invalid identifier (`__x`, `x__y`, `x_`), keyword used as a name; ambiguous unqualified enum literal; mixed STRING/WSTRING; `String[i] := String2`;
- assignment to a `CONSTANT` or to a `VAR_INPUT` inside its POU; `VAR_GLOBAL CONSTANT` used as a non-constant external; an FB instance in a CONSTANT section; RETAIN on VAR_IN_OUT;
- VAR_IN_OUT not properly mapped (literal/expression/constant actual); negation on an in-out; implicit conversion on an in-out actual (types must match exactly);
- non-formal call with the wrong number/order of parameters; a function without result used in an expression; `=>` to a non-variable;
- implicit conversion not in F12 (narrowing, signed→unsigned, int↔bit string, …) — explicit conversion required;
- arithmetic on BOOL/enums/strings; ordering compare on enumerations; operations on wrong operand types (T29 MOD needs ANY_INT; EXPT base ANY_REAL);
- literal array index out of bounds; too many/too few array initial values (**warning**);
- assignment to the FOR control variable inside the loop; FOR bounds of different integer types; a constant `BY 0`;
- a function/method result possibly never assigned;
- the forbidden FB accesses of F13 (`inst.In` read from outside, `inst.Out :=` from outside, in-out access outside the call);
- connector name clashing with another element; jump target outside the POU; uninitialised feedback variable;
- a missing feature (anything in §1 marked ❌).

Run time (must stop safely or set ENO := FALSE and be reported — never produce a plausible value silently):
- **division by zero** (integer and — per §7.3.2 a — any divide; `MOD 0` is defined as 0 and is NOT an error);
- **numeric overflow** of an operation or conversion result; out-of-range subrange value;
- array subscript out of range; MUX K out of range; negative shift count N; string position/length errors and over-long results; negative ANY_INT string inputs;
- dereferencing NULL / an unassigned interface; an in-out or instance input never given a value;
- a task overrun / missed deadline.
§5.1 e: every one of these must be listed in Kron's documentation of detected errors, with what happens (stop, ENO, log line).

## 17. Inconsistencies inside the standard and the reading to follow

- **Comparison precedence**: T71 gives `< > <= >= = <>` one level (4); the Annex A grammar puts relational above equality. Follow **Annex A** (`stExpr.js` does: `=`/`<>` bp 40, relational bp 50).
- **LIMIT non-formal argument order**: the graphical form lists `MN, IN, MX`; T20/§6.6.1.4.2 show `LIMIT(B, 0, 5)` "equivalent to `IN := B, MN := 0, MX := 5`". The graphical/declaration order is `MN, IN, MX`, so `LIMIT(0, B, 5)` is the strict reading; the T20 example contradicts it. **Prefer formal names in generated code and examples; for non-formal calls follow the existing Kron behaviour and document it** (`src/services/CLAUDE.md`: LIMIT/MUX emit by argument name).
- **`*_TO_BOOL`**: F11 shows "−" (no conversion) for every source → BOOL, but T24 defines `LWORD/DWORD/WORD/BYTE_TO_BOOL` (rightmost bit). T24 is the concrete feature: the bit-string → BOOL conversions exist; numeric → BOOL (`INT_TO_BOOL`) is not standard (extension if offered).
- **T25 example 2**: "`X := W;` and X gets 54 (=16#34)" — 16#34 is 52, and `X := W` (WORD → SINT) is not implicit per F11. Follow F11 (explicit `WORD_TO_SINT`) and the binary-transfer rule (16#34 = 52).
- **Empty string literal**: T6 1a/2a allow `''`/`""`; the Annex A rule `'\'' S_Byte_Char_Value + '\''` requires ≥ 1 character. Follow T6 (empty strings are valid).
- **Nested comments**: T3 3a/3b make nesting a feature; the Annex A comment rule is non-greedy (non-nesting). Kron supports nesting (`stripIecComments`) — keep.
- **VAR_TEMP / VAR_GLOBAL initialisers and NON_RETAIN on globals**: tables allow `VAR_TEMP I : INT := 1;` (T40 3d) and §6.5.6.2 allows NON_RETAIN on VAR_GLOBAL; the grammar omits both. Follow the tables.
- **Default access of FB statics**: §6.6.3.2 rule 11 says PRIVATE; F7 and classes say PROTECTED. Equivalent while Kron has no inheritance (PROTECTED = PRIVATE without inheritance, §6.6.5.9 note).
- **FOR example** writes `STEP -1` — the keyword is `BY` (Annex A).
- **CTD_ULINT** row of T45 says "PV, CV: UDINT" — a typo; ULINT intended.
